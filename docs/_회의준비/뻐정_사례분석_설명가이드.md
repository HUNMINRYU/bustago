# 뻐정 유사프로젝트 사례분석 — 구두 설명 가이드

> **담당 문서:** `docs/06_조사데이터/유사프로젝트_사례분석/뻐정_유사프로젝트_사례분석.md`  
> **설명 예상 시간:** 3~4분  
> **핵심 메시지:** "뻐정은 광주에서 이미 유사한 시도를 했고, 저희는 거기서 기술적 교훈을 얻어 세 가지를 개선했습니다."

---

## 1. 30초 요약 (교수가 "간단히 설명해봐"라고 물으면)

> "뻐정은 2022년에 광주에서 만든 버스 혼잡도 예측 서비스입니다.  
> 저희랑 비슷하게 CCTV + AI + LightGBM 모델을 썼습니다.  
> 저희는 뻐정이 해결 못한 중복 카운팅 문제를 DeepSORT로 해결했고,  
> SSD 대신 더 정확해진 YOLOv8을 쓰고, 혼잡도도 3단계에서 4단계로 늘렸습니다."

---

## 2. 설명 흐름 (단계별 말할 순서)

### Step 1 — 뻐정이 뭔가

말할 내용:
> "뻐정(Bbeojung.kr)은 광주 자연과학대학 학술제 프로젝트입니다.  
> 2022년에 개발됐고, GitHub에 코드와 블로그가 공개되어 있습니다.  
> 기존 CCTV에서 RTSP로 영상을 받아 SSD로 사람을 탐지하고,  
> LightGBM으로 시간대별 버스 수요를 예측해서 혼잡도를 제공했습니다."

### Step 2 — 뻐정의 기술 성과 (인정할 것)

말할 내용:
> "TensorRT를 써서 SSD 추론 속도를 기존 대비 24배 빠르게 만들었습니다.  
> 이는 저희가 Jetson에서 TensorRT를 쓰는 것과 같은 방식이고,  
> 뻐정의 사례가 저희 설계 방향이 검증된 접근임을 보여줍니다.  
> 또 200만 건 데이터로 LightGBM을 학습시켜 RandomForest보다 학습 속도가 15배 빨랐습니다."

### Step 3 — 뻐정의 한계 (차별점 도출)

말할 내용:
> "세 가지 한계가 있었습니다.  
> 첫째, 트래킹을 안 해서 같은 사람이 여러 번 카운팅되는 중복 문제가 있었고, 미해결 과제로 남겼습니다.  
> 둘째, SSD를 썼는데 당시 YOLO 초기 버전 정확도 한계를 이유로 채택하지 않았습니다.  
> 셋째, 혼잡도가 3단계(원활·보통·혼잡)라 세밀한 구분이 어렵습니다."

### Step 4 — BUSTAGO의 개선점

말할 내용:
> "첫째, DeepSORT Track ID로 중복 카운팅을 원천 차단했습니다.  
> 둘째, YOLOv8-nano를 씁니다. 2022년 이후 YOLO가 크게 개선되어 지금은 정확도 문제가 없습니다.  
> 셋째, 4단계 혼잡도로 더 세밀하게 제공합니다.  
> 추가로 기존 CCTV에 의존하는 대신 전용 카메라를 설치해서 카메라 각도와 위치를 직접 제어합니다."

## 3. 핵심 숫자 (반드시 암기)

| 항목 | 뻐정 | BUSTAGO |
|------|------|---------|
| **탐지 모델** | SSD | YOLOv8-nano |
| **트래킹** | 없음 (중복 카운팅 문제) | DeepSORT Track ID |
| **혼잡도 단계** | 3단계 | **4단계** (국토부 표준) |
| **TensorRT 속도** | 24배 향상 | Jetson TensorRT FP16 25~40 FPS |
| **ML 모델** | LightGBM (RandomForest 대비 15배 빠름) | RandomForest (CV 0.9962) |
| **데이터** | 200만 건 | 서울시 공공데이터 |
| **개발 연도** | 2022 | 2026 |

## 4. 예상 질문 & 답변

**Q: 뻐정이 먼저 해봤는데 왜 굳이 또 만드나요?**  
A: "뻐정은 기존 CCTV와 서버 중심 구조라 현장 제어가 어렵고, 중복 카운팅 문제를 해결하지 못했습니다. 저희는 전용 하드웨어(Jetson+Pi)를 설치해서 정확한 카운팅을 구현하고, 정류장 현장 디스플레이(키오스크)까지 제공합니다. 서비스 형태 자체도 다릅니다."

**Q: 뻐정이 LightGBM을 썼는데 왜 BUSTAGO는 RandomForest를 쓰나요?**  
A: "저희 모델은 7개 feature로 CV 0.9962라는 충분한 정확도가 나왔습니다. 훈련 데이터 규모가 다르고, 현재 시연 목표에서는 RandomForest로 충분합니다. 뻐정 사례에서 LightGBM이 더 효율적임을 확인했으므로, 향후 데이터가 쌓이면 교체를 검토할 수 있습니다."

**Q: RTSP 방식(뻐정)과 저희 CSI 카메라 방식의 차이가 뭔가요?**  
A: "RTSP는 기존 설치된 CCTV 영상을 네트워크로 수신하는 방식입니다. 카메라 위치와 각도를 바꿀 수 없고, CCTV 관리 권한도 필요합니다. CSI 케이블로 Jetson에 직접 연결하면 카메라 위치와 각도를 설계대로 설치하고 조정할 수 있습니다."

**Q: 뻐정이 이미 있는데 차별화 포인트가 뭔가요?**  
A: "① 중복 카운팅 해결(DeepSORT), ② 정확도 높은 YOLOv8 적용, ③ 4단계 혼잡도, ④ 현장 키오스크(Pi 화면)로 정류장에서 바로 확인 가능, ⑤ 학생 PWA + 운영자 대시보드 3가지 접점 지원입니다."
