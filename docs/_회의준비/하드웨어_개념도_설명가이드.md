# 하드웨어 시스템 개념도 — 구두 설명 가이드

> **담당 문서:** `docs/02_설계/하드웨어_시스템_개념도.md`  
> **설명 예상 시간:** 3~5분  
> **핵심 메시지:** "Pi 혼자서는 중복 카운팅을 막을 수 없어서 Jetson으로 바꿨고, Pi는 화면 전용으로 분리했습니다."

---

## 1. 30초 요약 (교수가 "간단히 설명해봐"라고 물으면)

> "저희 시스템은 정류장에 카메라 1대와 두 개의 보드가 있습니다.  
> Jetson은 AI 추론 전용 — 사람을 탐지하고 카운팅합니다.  
> Raspberry Pi는 화면 전용 — 학생들이 보는 키오스크를 띄웁니다.  
> 둘 다 WiFi로 서버에 연결되고, 서버에서 혼잡도를 계산해서 돌려줍니다."

---

## 2. 설명 흐름 (단계별 말할 순서)

### Step 1 — 왜 Pi에서 Jetson으로 바꿨나 (가장 중요)

말할 내용:
> "처음에는 Raspberry Pi 하나로 AI 추론과 화면 출력을 다 하려고 했습니다.  
> 그런데 Pi의 CPU로 YOLOv8을 돌리면 초당 2~5장(FPS)밖에 안 나옵니다.  
> 이 속도에서는 DeepSORT 트래커가 같은 사람을 프레임 사이에서 놓쳐버립니다.  
> 결과적으로 한 사람이 정류장에 들어왔는데 2명으로 카운팅되는 중복 문제가 생깁니다."

### Step 2 — Jetson이 어떻게 해결하나

말할 내용:
> "Jetson은 GPU 1024개 코어가 있어서 TensorRT FP16으로 초당 25~40장을 처리합니다.  
> 이 속도에서는 사람이 프레임 사이에서 거의 안 움직이기 때문에  
> DeepSORT가 동일 인물에게 고유 번호(Track ID)를 계속 유지할 수 있습니다.  
> 라인을 넘을 때 그 번호를 단 1회만 카운팅하고, 같은 번호가 다시 넘으면 무시합니다."

### Step 3 — 왜 카메라가 3대에서 1대로 줄었나

말할 내용:
> "원래 Pi로 할 때는 느린 FPS를 보완하려고 여러 각도에 카메라 3대를 두려고 했습니다.  
> Jetson이 25~40 FPS를 내면서 한 방향 카메라 1대로도 충분해졌습니다."

### Step 4 — 전체 데이터 흐름

말할 내용:
> "카메라 → Jetson(탐지·카운팅) → 10초마다 서버 POST  
> Pi → 60초마다 서버 GET(혼잡도 예측) → 화면에 표시  
> 운영자 PC → 서버 GET(통계·카운팅 현황) → 대시보드"

---

## 3. 핵심 숫자 (반드시 암기)

| 숫자 | 의미 |
|------|------|
| **2~5 FPS** | Pi 4 CPU의 YOLOv8 추론 속도 (중복 카운팅 원인) |
| **25~40 FPS** | Jetson GPU의 TensorRT FP16 추론 속도 (해결) |
| **1대** | 최종 카메라 수 (고 FPS 덕분에 1대로 충분) |
| **10초** | Jetson이 서버로 카운팅 데이터를 POST하는 주기 |
| **1024코어** | Jetson Orin Nano의 CUDA 코어 수 |

## 4. 예상 질문 & 답변

**Q: DeepSORT가 정확히 뭔가요?**  
A: "사람을 탐지한 후 각각에게 고유 번호를 붙여서 여러 프레임에 걸쳐 같은 사람임을 추적하는 알고리즘입니다. 칼만 필터로 다음 위치를 예측하고, 새 프레임의 탐지 결과와 매칭해서 번호를 유지합니다."

**Q: Jetson이 비싸지 않나요? Pi만 쓰면 안 되나요?**  
A: "Pi로는 중복 카운팅 방지가 기술적으로 불가능합니다. FPS가 낮아서 DeepSORT 자체가 동작하지 않습니다. Jetson의 추가 비용은 약 16만원이고, 이것 없이는 핵심 기능인 정확한 카운팅을 구현할 수 없습니다."

**Q: Jetson과 Pi가 따로 있는데 왜 Jetson 하나로 다 안 하나요?**  
A: "Jetson에서 AI 추론과 Chromium 화면을 동시에 돌리면 GPU 메모리가 경합해서 AI 성능이 떨어집니다. 각 보드가 하나의 역할에만 집중하도록 분리했습니다."

**Q: Line Crossing이 뭔가요?**  
A: "화면 안에 가상의 선 2개를 그어 놓습니다. IN 선을 넘으면 '정류장 진입', BOARD 선을 넘으면 '버스 탑승 완료'로 판단합니다. Track ID가 선을 1번 넘으면 1회 카운트하고, 같은 ID가 다시 넘으면 무시합니다."
