## 1. Executive Summary

**Release Decision: 🟡 Conditional Go.** 시스템은 동작하고 시연 가능하다. 치명적 빌드/런타임 블로커는 없다. 단, 아래 **3건의 의존성/배포 리스크**가 경진대회 전 정리 대상이다.

| # | 발견 | 심각도 | 근거 | 즉시성 |
|---|---|---|---|---|
| F1 | `.gitignore`가 Jetson YOLO export 산출물(`.torchscript/.mnn/.npy/_ncnn_model/`) 미차단 | **High** | `.gitignore` 직접 확인 — 해당 패턴 없음. D-12 현재 Jetson export 작업 활발 → 실수 커밋 위험 | 오늘 |
| F2 | `rf_model.pkl` git 미추적 + `.dockerignore` `*.pkl` 미제외 | **High** | `.gitignore:*.pkl` + `.dockerignore` grep 0건 → CI/clone 환경 Docker 빌드 시 모델 없는 이미지 생성 | 출시 전 |
| F3 | `backend/requirements.txt`의 `aiohttp` 미사용 | Medium | `grep -rn aiohttp backend/ ml/ hardware/` → requirements.txt 1줄만 | 오늘(저비용) |

**핵심 자산 경고**: `rf_model.pkl`(RandomForest 운영 모델), `yolo11n.pt`(YOLO 가중치), `data/features/train_features.csv`, `data/seoul_boarding/boarding_all.csv` 4개는 **전부 gitignore되어 저장소에 없다.** 로컬 디스크에만 존재 → **손실 시 복구 비용 큼. 별도 백업 필수.**

## 4. Architecture Findings

[종합점검 §2.1~2.5](종합점검_2026-05-22.md) 참조. 본 감사에서 추가 확인된 구조적 사실:

- **3-tier 폴백이 import-level에서 견고**: `congestion.py`가 `ml.models.predict`를 lazy import하고 `FileNotFoundError/ImportError`를 잡아 `rule_based` → DUMMY로 강등. rf_model.pkl 부재에도 앱 기동 보장. (Clean Architecture 관점: ML이 backend의 *plugin*으로 느슨히 결합됨 — 양호)
- **frontend↔backend 경계 명확**: `shared/api.js`가 단일 API 게이트웨이. base URL을 `window.location.origin`으로 동적 결정 → 배포 환경 무관. (의존 역전 양호)
- **seeds가 단일 진실원 역할 미완**: `gj_constants.py::STATIONS` dict는 광주 좌표를 갖지만 아무도 import 안 함(실제 좌표는 schema.sql INSERT에 중복 정의). DDD의 단일 진실원 위배 — Low.
