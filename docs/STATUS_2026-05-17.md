## 5. 작업 방식 — 진단 시리즈 사이클

오늘은 **"4개의 다른 관점으로 같은 코드베이스를 반복 진단"** 패턴 채택.

```
[외부 심사 관점]      → 보고서 v1.0 작성 + 약점 5개 + 질문 10개
       ↓
[외부 분석가 검증]    → 저장소 9페이지 대조 → 추가 강점 4 / 리스크 3 발견
       ↓
[Robert C. Martin]    → SOLID 위반 H1+H2 (단일 진실원) 발견 → 즉시 조치
       ↓
[Hennessy + Fowler]   → SI-1 시스템 통합 모순 (Rate Limiter) 발견 → Quick Wins 4건
       ↓
[Must 응답]           → 검증 결과 + 진단 결과를 사용자에게 보일 형태로 문서화
```

각 진단이 **서로 다른 결함을 발견**:
- 외부 심사: 약점 5개 (광주 검증 0건 / 0.9993 의심 / 시연 망 위험 등)
- 검증: 표면 약점 (claude contributor 사이드바 / main behind / Releases 0)
- Robert C. Martin: 코드 구조 (단일 진실원 위반)
- Hennessy + Fowler: 시스템 통합 (Rate Limiter + 워커 모순)

→ 학부 캡스톤에서 *진단 → 조치 → 검증* 사이클을 2일 연속(5/16 + 5/17) 유지한 것 자체가 발표 메타 강점.
