## 2. 시스템 개요

BUSTAGO는 광주광역시 대학교 캠퍼스를 대상으로 버스 정류장의 혼잡도를 예측하고 제공하는 시스템이다. 공공 교통 데이터와 기상 데이터를 기반으로 Random Forest 모델을 활용하여 혼잡도를 예측하며, YOLOv8을 통한 실시간 인원 감지 기능도 제공한다.

### 2.1 사용자 유형

| 사용자 유형 | 역할 | 주요 행동 |
|------------|------|----------|
| 학생 (승객) | 서비스 이용자 | 출발지-목적지 입력 → 노선 혼잡도 확인 → 탑승 결정 |
| 관리자 (운영자) | 시스템 관리자 | 전체 모니터링 → 통계 분석 → 모델 성능 관리 |
| 현장 이용자 | 정류장 방문자 | 현장 디스플레이에서 혼잡도 직접 확인 |

## 3. 전체 업무 흐름도 v2

### 3.1 개요

v2는 시스템 Phase 흐름과 사용자 여정을 **2레인(System Lane / User Lane)** 으로 병행 표현한다.

```
┌──────────────────────────────────────────────────────────────────┐
│                    BUSTAGO 업무 흐름도 v2                          │
│                                                                  │
│  ┌─ USER LANE ────────────────────────────────────────────────┐  │
│  │                                                            │  │
│  │  [학생] PWA 접속 → 출발지/목적지 입력 → 노선+혼잡도 확인    │  │
│  │         → 대체노선 선택 → 탑승 → (만족도 피드백)            │  │
│  │                                                            │  │
│  │  [관리자] 대시보드 접속 → 인증 → 모니터링/통계/모델관리      │  │
│  │                                                            │  │
│  │  [현장이용자] 정류장 디스플레이에서 혼잡도 직접 확인          │  │
│  │                                                            │  │
│  └────────────────────────────────────────────────────────────┘  │
│         ↕ API 호출/응답        ↕ 데이터 피드백                    │
│  ┌─ SYSTEM LANE ──────────────────────────────────────────────┐  │
│  │                                                            │  │
│  │  Phase 1        Phase 2         Phase 3        Phase 4     │  │
│  │  데이터 수집 →  처리/분석 →     서비스 제공 →   저장/관리    │  │
│  │                                                            │  │
│  └────────────────────────────────────────────────────────────┘  │
└──────────────────────────────────────────────────────────────────┘
```

## 4. Phase 1: 데이터 수집

### 4.1 시스템 처리

## 5. Phase 2: 데이터 처리 및 분석

### 5.1 시스템 처리

```
[원시 데이터]
     │
     ▼
[전처리 (build_features.py)]
  - 시간대별 집계
  - 결측치 처리
  - Feature Engineering: hour, weekday, weather, temperature,
                         prev_boarding, prev_alighting, route_count
     │
     ├──→ [Random Forest 예측 경로]
     │      train_rf.py → congestion_model.pkl
     │      - n_estimators=10, max_depth=10
     │      - 7 features, CV 0.9962
     │      - 혼잡도 4단계 분류
     │
     └──→ [YOLOv8 실시간 경로] (Phase 2)
            - Pi Camera 영상 입력
            - 사람 객체 탐지 → 인원 카운팅
            - DeepSORT 트래킹 (중복 카운팅 방지)
```

### 5.2 사용자 터치포인트

| 사용자 | 행동 | 시스템 반영 |
|--------|------|-----------|

| 학생 | (없음 — 분석은 자동) | — |

## 6. Phase 3: 서비스 제공

### 6.1 학생 (승객) 서비스 — 사용자 여정

```
[학생 여정]

① PWA 접속 (홈 화면 아이콘 or 브라우저)
     │
② 출발지 설정
     │  - GPS 자동감지 (인성관/정문 반경 100m)
     │  - 또는 드롭다운 수동 선택
     │
③ 목적지 입력
     │  - 직접 입력 or 즐겨찾기
     │  - 예: "광주역", "충장로", "금남로"
     │
④ 노선 목록 + 혼잡도 확인
     │  - 419번 🟠혼잡, 518번 🟢여유
     │  - 셔틀 4호차 🔴매우혼잡 (만차 확률 87%)
     │
⑤ 탑승 결정
     │  - 여유/보통 → 바로 탑승
     │  - 혼잡/매우혼잡 → 대체 노선 선택
     │
⑥ 시간대 예측 확인 (선택)
     │  - 30분/1시간 후 혼잡도 변화 그래프
     │
⑦ 탑승 완료
```

### 6.2 서비스 항목

| 서비스 | 대상 | 설명 |
|--------|------|------|
| PWA 혼잡도 조회 | 학생 | 출발지-목적지 기반 노선별 혼잡도 + 대체노선 추천 |
| 현장 디스플레이 | 현장 이용자 | Pi + 7인치 화면에 현재 혼잡도 + 30분 예측 표시 |
| 웹 대시보드 | 관리자 | 지도 모니터링 + 통계 + 실시간 영상 + 모델 관리 |

### 6.3 관리자 서비스

| 서비스 항목 | 설명 |
|------------|------|
| 지도 모니터링 (Leaflet.js) | 전체 정류장 혼잡도 한눈에 확인 |
| 혼잡도 통계 (Chart.js) | 시간대별 바차트 + 혼잡도 분포 도넛차트 |
| 실시간 영상 (Phase 2) | YOLOv8 카메라 1대 (Jetson GPU, 25~40 FPS) + DeepSORT 인원 카운팅 현황 |
| 모델 성능 리포트 | 정확도, 오차율 등 성능 지표 확인 + 재학습 트리거 |

## 7. Phase 4: 데이터 저장 및 관리

### 7.1 시스템 처리

| 관리 항목 | 설명 |
|----------|------|
| DB 저장 | 예측 결과, 실측 혼잡도, 사용자 조회 로그를 SQLite/MySQL에 이력 저장 |
| 데이터 보존 | 학습 가치 있는 이력 장기 보존 → 모델 재학습에 활용 |
| 데이터 정리 | 보존 기한 경과 로그 삭제 → 저장 공간 관리 |
| **피드백 루프** | 축적 데이터로 모델 재학습 → 예측 품질 지속 개선 |

### 7.2 사용자 터치포인트

| 사용자 | 행동 | 시스템 반영 |
|--------|------|-----------|
| 관리자 | 모델 재학습 수동 실행 (UC-09) | 최신 데이터로 모델 갱신 |
| 관리자 | CSV 다운로드 (FR-305) | 혼잡도 데이터 외부 분석용 추출 |
