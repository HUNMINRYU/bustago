### 2.1 ML 혼잡도 모델용 — 광주대 승하차 데이터 (보류)

- **현황**: 광주 BIS API는 도착 정보·노선·정류소만 제공. **차내 혼잡도·승하차 이력은 미제공**.

- **우회**: 시연·대회는 "서울 모델 + 광주 카운팅 데이터 결합"으로 진행하며, 본 한계는 `모델_신뢰성_한계_진술서.md`에 명시.

## 6. 학습 데이터 vs 평가 데이터 분리 기준

**가장 중요한 원칙**: 영상 단위 grouping. 한 영상의 모든 프레임은 train 또는 val 또는 eval 한 군데에만 들어간다 (data leak 방지).

| 데이터 셋 | 용도 | 입력 | 비중 |
|---|---|---|---|
| `self_v1/images/train` | YOLO fine-tune 학습 | 시연 영상 + 5/22 보강 영상 80% | 80% |
| `self_v1/images/val` | mAP 측정 (Detection 평가) | 동일 풀에서 별도 영상 20% | 20% |
| `eval_videos/*.mp4` | Counting IN/BOARD 오차율 측정 | 5/23 또는 5/30 별도 촬영 | 학습에 미포함 |

→ `eval_videos`는 학습 데이터에 포함되지 않은 영상이라 *진정한 generalization* 측정.

### B.2 카메라 각도·위치 설정

**목표 시야각**: 정류장 진입 통로 전체가 한 화면에 들어오고, 사람이 좌우로 이동하는 동선이 잡혀야 함.

```
[카메라 시점]

     카메라 (1.5~2m 높이)
          |
          v
  ---[IN 라인 x=70%]---[BOARD 라인 x=30%]---
  버스 출발 방향 (좌)        정류장 진입 방향 (우)
```

- **IN 라인 (파란, x=70%)**: 오른쪽에서 왼쪽으로 통과 = 정류장 진입
- **BOARD 라인 (초록, x=30%)**: 더 왼쪽으로 이동 = 버스 탑승
- 카메라가 정면 또는 약간 위에서 내려보는 각도(부감, 약 20~30도)여야 ID 유지 우수
- 역광(뒤에서 햇빛)이 오면 카메라 방향을 햇빛 방향으로 돌리거나 시간대 변경

**현장 확인 방법 (디버그 모드)**:

```bash
cd ~/bustago/hardware
python3 counter.py --camera 0 --model yolo11n.pt --debug
# 화면에 IN/BOARD 세로 라인 오버레이가 보여야 함
# 사람이 우→좌로 이동할 때 IN 카운터가 올라가는지 확인
# Ctrl-C로 종료
```

### B.3 녹화 명령 — 그대로 복붙

**정류장 ID 및 파일명 규칙**: `{STATION}_{YYYYMMDD_HHMM}_{N}min.mp4`

예시: `INS01_20260524_0800_5min.mp4`

  --duration 300 \
  --station INS01 \

  --duration 300 \
  --station INS01 \
  --output "${OUTPUT_DIR}/INS01_20260524_1200_5min.mp4"

  --duration 300 \

**녹화 중 메모 사항 (종료 후 .meta.json에 기입)**:

## E. 라벨링 절차 — eval_counting.py 활용

### E.1 사후 수동 라벨링 방법

촬영 완료된 영상을 *사람이 재생하면서* 라인 통과 횟수를 수동 카운트. 1분 영상 = 5~15분 작업.

```
준비물: 영상 재생 + 수기 카운팅 노트 + 타임스탬프 기록

1단계: 영상 재생 (0.5~0.75배속 권장)
2단계: IN 라인(화면 우측 70%) 통과마다 정표(正) 표시
3단계: BOARD 라인(화면 좌측 30%) 통과마다 별도 정표
4단계: 총합 집계 → groundtruth JSON 작성
```

### E.2 groundtruth JSON 작성 예시

파일명: `{영상 stem}_groundtruth.json`
예시: `INS01_20260524_0800_5min_groundtruth.json`

```json
{
  "video": "INS01_20260524_0800_5min.mp4",
  "station_id": "INS01",
  "labeler_a": "류훈민",
  "labeler_b": "박건우",
  "ground_truth": {
    "count_in": 23,
    "count_board": 19
  },
  "labeler_a_raw": {
    "count_in": 23,
    "count_board": 20
  },
  "labeler_b_raw": {
    "count_in": 22,
    "count_board": 19
  },
  "consensus": "평균 사용 (차이 1 이내)",
  "notes": "07:58~08:03 우산 든 그룹 3명 — ID 분기 가능성 있음",
  "labeled_at": "2026-05-25T14:30:00+09:00"
}
```

> `ground_truth.count_in/board`는 A·B 카운트 합의값. **이 숫자가 eval_counting.py 기준.**

### E.3 라벨러 2명 교차 검증 규칙

| 차이 | 조치 |
|---|---|
| 0~1건 차이 | 두 값 평균 사용 (반올림) |
| 2~3건 차이 | 문제 구간 재생·재카운트 후 합의 |
| 4건 이상 차이 | 제3자(이건영) 재카운트 → 다수결 |

├── INS01_20260524_0800_5min_groundtruth.json
├── GATE01_20260527_0800_5min.mp4
└── GATE01_20260527_0800_5min_groundtruth.json

## G. 정확도 측정 — eval_counting.py 실행

### G.1 실행 명령 — 그대로 복붙

```bash
cd ~/bustago/hardware

# baseline 모델 1개 측정
python3 eval_counting.py \
  --video   ~/bustago/datasets/bustago_person/self_v1/eval_videos/INS01_20260528_1700_5min.mp4 \
  --groundtruth ~/bustago/datasets/bustago_person/self_v1/eval_videos/INS01_20260528_1700_5min_groundtruth.json \
  --models  yolo11n.pt \
  --output  ~/bustago/docs/04_테스트/eval_results/INS01_20260528_baseline.csv

# baseline + fine-tune 비교 (fine-tune 완료 후)
python3 eval_counting.py \
  --video   ~/bustago/datasets/bustago_person/self_v1/eval_videos/INS01_20260528_1700_5min.mp4 \
  --groundtruth ~/bustago/datasets/bustago_person/self_v1/eval_videos/INS01_20260528_1700_5min_groundtruth.json \
  --models  yolo11n.pt runs/detect/train/weights/best.pt \
  --output  ~/bustago/docs/04_테스트/eval_results/INS01_20260528_compare.csv

# 여러 영상 연속 측정 (eval_videos 전체 반복)
for VIDEO in ~/bustago/datasets/bustago_person/self_v1/eval_videos/*.mp4; do
  GT="${VIDEO%.mp4}_groundtruth.json"
  STEM=$(basename "$VIDEO" .mp4)
  if [[ -f "$GT" ]]; then
    python3 eval_counting.py \
      --video "$VIDEO" \
      --groundtruth "$GT" \
      --models yolo11n.pt \
      --output "~/bustago/docs/04_테스트/eval_results/${STEM}_eval.csv"
  fi
done
```

### G.2 출력 CSV 해석

eval_counting.py가 출력하는 CSV 컬럼:

| 컬럼 | 의미 | 합격 기준 |
|---|---|---|
| `model` | 모델 파일명 | — |
| `video` | 영상 파일명 | — |
| `ai_in` | AI가 측정한 IN 카운트 | — |
| `gt_in` | 사람이 라벨링한 IN 카운트 | — |
| `in_error_pct` | IN 오차율(%) = \|ai_in - gt_in\| / gt_in × 100 | **≤ 15%** |
| `ai_board` | AI BOARD 카운트 | — |
| `gt_board` | GT BOARD 카운트 | — |
| `board_error_pct` | BOARD 오차율(%) | **≤ 20%** |

**시연_계획서 §1.2 기준**: 오차 ±2명 이내 → 5분 영상 통과 인원 ~20명 기준 10% 오차.
