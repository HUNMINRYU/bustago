# BUSTAGO 시스템 플로우차트 v2

> **작성일:** 2026-04-10  
> **버전:** v2.0 — 피드백 반영 (사용자 기준 흐름 + 출발지-목적지 + 구체적 버스번호)  
> **변경 사유:** 1차 리뷰 피드백: "사용자 기준으로 흐름도 재작성", "몇 번 버스인지 구체적으로", "대체노선추천에 출발지-목적지 필요"

---

## 1. v1 → v2 변경 요약

| 항목 | v1 | v2 |
|------|----|----|
| 관점 | 시스템 내부 (데이터 유무 분기) | **사용자 여정** (목적 → 행동 → 결과) |
| 정류장 선택 | 이름/번호 검색만 | **출발지 + 목적지** 입력 |
| 대체 노선 | "대체 노선 추천" (추상적) | **구체적 버스번호** + 혼잡도 비교 |
| 혼잡도 단계 | 3단계 (여유/보통/혼잡) | **4단계** (여유/보통/혼잡/매우혼잡) — 구현과 일치 |
| 시나리오 | 없음 | 광주대 실제 노선 기반 시나리오 포함 |

### 3.2 단계별 상세 설명

| 순서 | 블록 | 단계명 | 설명 |
|------|------|--------|------|
| 1 | 시작 | Start | 사용자가 BUSTAGO PWA에 접속한다 |
| 2 | 프로세스 | PWA 앱 접속 | 모바일 브라우저 또는 홈 화면 아이콘으로 접속. 별도 설치 불필요 |
| 3 | 프로세스 | **출발지 입력** | GPS 기반 자동 감지(인성관/정문 반경 100m 이내 시) 또는 드롭다운 수동 선택 |
| 4 | 프로세스 | **목적지 입력** | 목적지를 직접 입력하거나 즐겨찾기(광주역, 충장로 등)에서 선택 |
| 5 | 프로세스 | 경로 탐색 | 광주 BIS API로 출발 정류장→목적지 경유 노선을 조회. 각 노선의 혼잡도를 ML 모델로 예측 |
| 6 | 분기 | 이용 가능 노선? | 매칭되는 노선이 없으면 안내 메시지 표시 후 종료 |
| 7 | 프로세스 | **노선 목록 + 혼잡도** | 이용 가능한 모든 노선을 혼잡도(4단계 색상)와 함께 리스트 표시. **버스번호 명시** |
| 8 | 분기 | 혼잡도 등급 판정 | 사용자가 선택한 노선의 혼잡도에 따라 분기 |
| 9-여유 | 프로세스 | 탑승 안내 | 여유/보통이면 해당 노선 탑승을 안내 ("419번 약 5분 후 도착, 여유") |
| 9-혼잡 | 프로세스 | **대체 노선 추천** | 혼잡/매우혼잡이면 같은 목적지의 대체 노선을 **버스번호와 혼잡도**와 함께 표시 |
| 10 | 분기 | 30분 후 예측? | 사용자가 시간대별 예측 그래프를 확인할지 선택 |
| 11 | 프로세스 | 예측 표시 | 30분/1시간 후 혼잡도 변화 그래프(Chart.js)를 표시 |
| 12 | 종료 | End | 서비스 이용 종료 |

## 4. 관리자 (운영자) 시스템 플로우차트 v2

### 4.1 흐름도

```
[시작]
  │
  ▼
[웹 대시보드 접속]
  │
  ▼
  ◇ 관리자 인증 성공? ◇
  │                   │
  Yes                 No
  │                   │
  │                   ▼
  │            [로그인 재시도]──→ (3회 실패 시 잠금)
  │
  ▼
[대시보드 메인 (지도 뷰)]
  │
  ├──→ [A. 지도 모니터링]
  │      └─ Leaflet.js 기반 전체 정류장 혼잡도 현황
  │         (인성관 🟡보통, 정문 🟠혼잡 ...)
  │
  ├──→ [B. 혼잡도 통계]
  │      └─ 시간대별 바차트 + 도넛차트(혼잡도 분포)
  │         노선별 만차 빈도 (1호차~6호차)
  │
  ├──→ [C. 실시간 영상]
  │      └─ YOLOv11 + DeepSORT 인원 카운팅 오버레이
  │         Jetson Orin Nano + Pi Camera v2 (1대, 25~40 FPS)
  │
  └──→ [D. 모델 관리]
         │
         ▼
    ◇ 정확도 기준(80%) 이하? ◇
    │                        │
    Yes                      No
    │                        │
    ▼                        ▼
  [모델 재학습 실행]    [정상 운영 유지]
    │
    ▼
  [재학습 결과 리포트]
    │
    ▼
  [종료]
```

### 4.2 단계별 상세 (v1 대비 변경점)

| 변경점 | v1 | v2 |
|--------|----|----|
| 인증 실패 | 단순 리다이렉트 | **3회 실패 시 잠금** (보안 강화) |
| 실시간 영상 | 카메라 1대 (Pi CPU) | **카메라 1대 (Jetson GPU, 25~40 FPS)** + DeepSORT 트래킹 |
| 통계 차트 | 히트맵 언급 | **바차트 + 도넛차트** (실제 구현과 일치) |
| 자동 갱신 | 미언급 | **60초 자동 갱신** (dashboard.js REFRESH_MS=60000) |

## 5. 구체적 시나리오 예시

### 시나리오 1: 인성관 → 광주역 (셔틀 만차 시)

```
학생 김OO, 16:10에 PWA 접속

1. 출발지: 광주대 인성관 (GPS 자동 감지)
2. 목적지: 광주역

[경로 탐색 결과]
  ┌─────────────────────────────────────┐
  │ 🚌 셔틀 4호차 (16:20 출발)  🔴 매우혼잡 │
  │    만차 확률 87% — 탑승 어려움         │
  │                                     │
  │ 🚍 419번 (정문 정류장)      🟠 혼잡    │
  │    약 8분 후 도착, 광주역 직행          │
  │                                     │
  │ 🚍 518번 (정문 정류장)      🟢 여유    │
  │    약 12분 후 도착, 금남로역 환승        │
  │                                     │
  │ 💡 추천: 518번 이용 (도보 5분→정문)     │
  └─────────────────────────────────────┘

3. 학생이 518번 선택
4. "정문 정류장까지 도보 약 5분, 518번 약 12분 후 도착" 안내
5. 30분 후 예측: 셔틀 5호차(16:40) 🟡보통 → "다음 셔틀 이용도 가능"
```

### 시나리오 2: 정문 → 충장로 (여유 시간대)

```
학생 박OO, 10:30에 PWA 접속

1. 출발지: 광주대 정문
2. 목적지: 충장로

[경로 탐색 결과]
  ┌─────────────────────────────────────┐
  │ 🚍 419번                  🟢 여유    │
  │    약 5분 후 도착, 충장로 직행          │
  │                                     │
  │ 🚍 518번                  🟢 여유    │
  │    약 15분 후 도착                    │
  └─────────────────────────────────────┘

3. "419번 탑승을 추천합니다 (여유, 5분 후 도착)"
4. 학생이 바로 탑승
```

## 6. 데이터 흐름 (v2 기준)

```
[사용자 입력]          [시스템 처리]              [데이터 소스]
출발지 + 목적지  ──→  경로 탐색 API  ◀──────  광주 BIS API (노선-정류소)
                      │
                      ▼
                 각 노선별 혼잡도 예측  ◀──  ML predict.py (RF 모델)
                      │                      │
                      │                      ◀── 기상청 API (날씨)
                      │                      ◀── 승하차 이력 DB
                      ▼
                 노선 목록 정렬 (혼잡도 낮은 순)
                      │
                      ▼
                 JSON 응답 → PWA 렌더링
```
