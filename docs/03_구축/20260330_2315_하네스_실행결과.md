## 1. 실행 개요

BUSTAGO 프로젝트의 전체 스택을 에이전트 팀 하네스로 자동 구축하였다.
ML 파이프라인(Phase 2) 완성 후 Backend + Frontend + QA를 병렬(Phase 3)로 진행하는 2단계 팀 구성을 적용하였다.

### 실행 흐름

```
Phase 1: 준비 -- _workspace/ 생성, Feature 스키마 추출
Phase 2: ML 팀 (ml-engineer 단독)
  → collect_congestion.py, pipeline.py, train_rf.py, predict.py
  → _workspace/01_ml_model_contract.json 생성
Phase 3: 앱 팀 (backend + frontend + qa 병렬)
  → Backend: Flask 앱 + API 4개 엔드포인트
  → Frontend: 학생 PWA + 운영자 대시보드
  → QA: 4단계 교차 검증 (점진적)
Phase 4: 통합 검증 -- QA FAIL 항목 직접 수정
Phase 5: 정리 -- 팀 해산, 결과 요약
```

## 2. 생성된 파일 목록

### 2.1 ML 파이프라인

| 파일 | 역할 | 크기 |
|------|------|------|
| `ml/data_collection/collect_congestion.py` | 버스도착정보 API 혼잡도 데이터 수집 | 5,199B |
| `ml/data_collection/pipeline.py` | 수집 파이프라인 통합 오케스트레이터 (--step 옵션) | 4,308B |
| `ml/models/train_rf.py` | RandomForest 학습 (n=10, 5-fold CV, 80/20 split) | 5,138B |
| `ml/models/predict.py` | 예측 인터페이스 (predict_congestion / predict_batch) | 4,847B |

**모델 사양** (Autoresearch 최적화 후 — 2026-03-31 업데이트):
- 알고리즘: RandomForestClassifier
- Feature: hour, weekday, weather, temperature, prev_boarding, prev_alighting, route_count (7개)
- 제거된 Feature: rain(노이즈), boarding/alighting(leakage 위험)
- Label: 0(여유), 1(보통), 2(혼잡), 3(매우혼잡) — 4단계 분류
- 하이퍼파라미터: n_estimators=10, max_depth=10, min_samples_leaf=5, max_features=sqrt, random_state=42
- 성능: CV Mean Accuracy 0.9962, 모델 크기 0.2MB (기존 5.1MB → 96% 감소)
- 출력 경로: `ml/models/rf_model.pkl`

## 4. 데이터 흐름 (E2E)

```
[예측 요청]
Frontend: fetchPredict(stationId, hour, weekday)
  → GET /api/predict?station_id=22011&hour=8&weekday=1
  → Backend: features dict 7개 구성 (hour, weekday, weather, temperature, prev_boarding, prev_alighting, route_count)
  → ML: predict_congestion(features, model_path)
  → {level: 0-3, label: str, probabilities: [float×4]}
  → Backend: jsonify({status, data: {prediction, recommendation, next_hour_prediction}})
  → Frontend: data.prediction.level → 색상 + 라벨 표시

[통계 조회]
Frontend: fetchStats(stationId, period)
  → GET /api/stats?station_id=22011&period=today
  → Backend: predictions 테이블 시간대별 평균 집계
  → Frontend: hourly_stats → Chart.js 바 그래프

[정류장 목록]
Frontend: fetchStations()
  → GET /api/stations
  → Backend: DB stations 테이블 전체 조회
  → Frontend: 드롭다운 동적 구성 (학생 + 운영자 양쪽)

[날씨 조회]
Frontend: fetchWeather()
  → GET /api/weather/current
  → Backend: 캐시 확인 → 기상청 API → 폴백
  → Frontend: 날씨 아이콘 + 온도 표시
```
