## 1. 시연 목표 및 성공 기준

### 1.1 시연 목표

- 학생 사용자가 모바일 PWA에서 정류장 혼잡도를 직관적으로 확인하고 탑승 판단에 활용할 수 있음을 보여준다.
- Jetson Orin Nano 기반 AI 카운팅이 실시간 대기인원과 탑승 흐름을 안정적으로 수집함을 검증한다.
- 운영자가 Admin 대시보드에서 핵심 지표, 실시간 카운팅, 차트, 지도를 통해 전체 상황을 즉시 파악할 수 있음을 입증한다.
- 제한된 시연 시간 내에 학생용 서비스와 운영자용 관리 기능이 하나의 통합 시스템으로 연결되어 동작함을 제시한다.

### 1.2 성공 기준

| 구분 | 성공 기준 |
| --- | --- |
| PWA 조회 응답 | 정류장 선택 후 현재 혼잡도 화면 표시까지 3초 이내 |
| 예측 차트 표시 | 시간대별 6시간 예측 차트 로딩 3초 이내 |
| AI 카운팅 정확도 | 시연 구간에서 실제 이동 인원 대비 오차 ±2명 이내 |
| 실시간 반영 지연 | Jetson 이벤트 발생 후 Admin 패널 수치 반영까지 2초 이내 |
| 대시보드 안정성 | 10분 시연 동안 치명적 화면 멈춤 또는 새로고침 필요 상황 0회 |
| 오프라인 대응 | 네트워크 차단 시 5초 이내에 오프라인 Fallback 화면 전환 |

## 3. 시연 시나리오 (총 약 10분)

| 단계 | 시간 | 시연 내용 | 확인 포인트 |
| --- | --- | --- | --- |
| 1. 시스템 시작 확인 | 2분 | Jetson 카운팅 서비스 ON 확인, Raspberry Pi 4 키오스크 화면 확인, 서버 상태 페이지 또는 로그 확인 | 서비스 실행 상태, 장치 연결 상태, 초기 화면 정상 여부 |
| 2. 학생 PWA 시연 | 3분 | 정류장 선택 → 현재 혼잡도 확인 → 노선 추천 확인 → 시간대별 예측 차트 확인 | 조회 응답 속도, 혼잡도 인디케이터 표시, 추천 흐름의 직관성 |
| 3. AI 카운팅 시연 | 2분 | 시연자가 카메라 앞에서 이동하거나 탑승 흐름을 모사 | IN/OUT 또는 BOARD 관련 수치 변화, 카운팅 반영 지연 |
| 4. Admin 대시보드 시연 | 2분 | 실시간 카운팅 패널과 시간대별 차트, 지도 상태 갱신 확인 | Summary 지표, 실시간 패널 값 갱신, 마커 색상 및 차트 업데이트 |
| 5. Q&A 및 마무리 | 1분 | 주요 성과 요약, 질의응답, 향후 확장 방향 언급 | 시연 메시지 정리, 질의 대응 마무리 |

### 3.1 단계별 진행 멘트 기준

1. 시스템 시작 확인: 장치 연결과 서비스 기동 상태를 먼저 보여주고, 데이터 수집부터 사용자 화면까지 하나의 흐름으로 연결된다는 점을 설명한다.
2. 학생 PWA 시연: 학생 입장에서 가장 빠르게 필요한 정보가 무엇인지 설명하며, 혼잡도와 추천 정보가 의사결정에 어떻게 쓰이는지 강조한다.
3. AI 카운팅 시연: 실제 움직임에 따라 카운트가 바뀌는 모습을 보여주고, 하드웨어와 대시보드가 실시간으로 연결되어 있음을 확인시킨다.
4. Admin 대시보드 시연: 운영자가 여러 정류장을 동시에 감시하고 판단할 수 있다는 운영 효율 측면을 설명한다.
5. Q&A 및 마무리: 시연 목표 달성 여부와 향후 고도화 포인트를 간단히 정리한다.

## 5. 장애 대응 플랜

### 5.1 WiFi/네트워크 끊김 시

1. 박건우가 교내 WiFi 상태를 즉시 확인하고 예비 핫스팟으로 전환한다.
2. 류훈민은 청중에게 오프라인 대비 기능 또는 캐시 기반 화면을 설명하며 발표 흐름을 유지한다.
3. 네트워크 복구 후 PWA와 Admin 페이지를 재연결하고 최신 데이터 수신 여부를 확인한다.

### 5.2 Jetson Orin Nano 다운 시

1. 이트겔이 Jetson 전원, 서비스 프로세스, 카메라 연결 상태를 즉시 점검한다.
2. 1분 내 복구가 어려우면 마지막 정상 수집 데이터 또는 사전 저장된 데모 로그 화면으로 전환한다.
3. 이건영은 Admin 대시보드의 집계/예측 기능 위주로 시연을 이어가고, 실시간 카운팅은 복구 후 재시도한다.

### 5.3 백엔드 서버 다운 시

1. 서버 상태 페이지, 프로세스 상태, 포트 응답을 우선 확인한다.
2. 재기동 가능하면 즉시 서비스 재시작 후 PWA와 Admin 대시보드 새로고침을 수행한다.
3. 즉시 복구가 불가하면 캐시된 PWA 화면과 사전 캡처된 Admin 스크린샷 또는 로컬 백업 데이터로 핵심 기능 설명을 진행한다.

### 5.4 PWA 로딩 실패 시

1. 모바일 브라우저 캐시 및 Service Worker 상태를 확인하고 새로고침 또는 홈 화면 재실행을 시도한다.
2. 동일 문제가 지속되면 예비 모바일 기기에서 동일 URL 또는 설치형 PWA를 실행한다.
3. 최종적으로 모바일 시연이 어려우면 노트북 브라우저의 모바일 뷰로 학생 흐름을 대체 시연한다.
