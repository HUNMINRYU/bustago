# 시연환경 초기세팅 마스터 가이드 — 빈 장비에서 시연 완료까지

> **목적:** 새 부스/회의실/현장에서 Jetson·Pi·노트북·카메라를 처음부터 세팅해 BUSTAGO 시연이 동작할 때까지의 **전체 순서**를 한 페이지에 모은 플레이북.
> **대상:** 본인 또는 인계받은 팀원. 처음 가본 장소에서도 막힘없이 진행 가능하도록.
> **사용법:** 위에서부터 순서대로. 각 단계는 더 자세한 문서를 가리킨다.
> **사전 전제:** GitHub develop 브랜치(`8e34c9f` 이상 — 카카오 지도·서울 정류장 제거 반영)가 빌드 완료된 상태.

### 0.2 사전 자산 백업 (출발 전)
다음 4개 파일은 **gitignore라 저장소에 없음** — USB로 따로 챙겨야 함:
```bash
mkdir -p ~/bustago_assets

cp ~/bustago/yolo11n.engine          ~/bustago_assets/   # TensorRT 엔진 (Jetson에서 생성한 것)

# USB에 ~/bustago_assets 전체 복사
```

## Phase 2.7 — 카카오 지도 키 설정 (대시보드 지도 전용, 10분)

> 대시보드(`/admin/`)의 정류장 지도에만 필요. **학생앱·키오스크는 지도 미사용이라 무관.**
> 키를 안 넣어도 지도 자리에 "키 필요" 안내 박스만 뜨고 **나머지 대시보드는 정상 동작** — 시연 필수는 아님.

### 2.7.1 키 발급
1. https://developers.kakao.com → 로그인 → **내 애플리케이션** → 앱 생성(또는 기존 앱)
2. **앱 키** → **JavaScript 키** 복사

### 2.7.2 `.env`에 키 입력 (Jetson)
```bash
cd ~/bustago
# .env의 KAKAO_MAP_APP_KEY= 줄에 발급받은 JavaScript 키 붙여넣기
# (.env가 없으면 cp .env.example .env 후 편집)
nano .env      # KAKAO_MAP_APP_KEY=발급키
```
> `.env`는 gitignore라 저장소에 안 올라감. 키는 매 환경마다 직접 입력해야 함.

### 2.7.3 카카오 콘솔에 도메인 등록 (★ IP 바뀌면 매번)
카카오 developers → 내 앱 → **플랫폼** → **Web** → **사이트 도메인**에 시연 origin 등록:
```
http://localhost:5000
http://<JETSON_IP>:5000      ← Phase 1.2에서 메모한 IP. 포트 :5000까지!
```
> **이게 시연 현장에서 가장 빠뜨리기 쉬운 단계.** Jetson IP가 바뀌면 지도가 안 뜨므로 그때마다 재등록 필요. 등록은 즉시 반영됨(재배포 불필요).

### 2.7.4 확인
백엔드 재시작 후 노트북 브라우저에서:
```
http://<JETSON_IP>:5000/admin/
```
→ "정류장 지도" 패널에 카카오 지도 + 정류장 마커가 뜨면 성공.
→ 안내 박스만 뜨면: 키 미입력(2.7.2) 또는 도메인 미등록(2.7.3) 확인.

## Phase 3 — Jetson 단독 E2E 스모크 테스트 (15분)

Pi가 도착하기 전에 노트북만으로 동작 검증.

### 3.1 백엔드 기동 (Jetson 터미널 ①)
```bash
cd ~/bustago && python3 -m backend.app
# "Running on http://0.0.0.0:5000" 확인
```

### 3.2 노트북에서 헬스체크
노트북·Jetson 같은 WiFi에 있는 상태에서:
```bash
ping -c 2 <JETSON_IP>
curl "http://<JETSON_IP>:5000/api/health"
# → {"status":"ok",...}
curl -I "http://<JETSON_IP>:5000/admin/"
# → HTTP/1.1 200 OK
```

### 3.3 cURL E2E 시나리오 (DEMO01 흐름)
```bash
JIP=<JETSON_IP>   # 예: 192.168.0.42
curl -X POST http://$JIP:5000/api/crowd-count/reset \
  -H "Content-Type: application/json" -d '{"station_id":"DEMO01"}'
# → {"status":"ok","deleted_rows":0}

curl -X POST http://$JIP:5000/api/crowd-count/event \
  -H "Content-Type: application/json" -d '{"station_id":"DEMO01","event_type":"in"}'
# → count_in=1, current_waiting=1

curl "http://$JIP:5000/api/crowd-count/recent?station_id=DEMO01&limit=5"
# → events 1건
```

### 3.4 카운터 기동 (Jetson 터미널 ②)
```bash
cd ~/bustago/hardware
python3 counter.py --camera 0 --model ~/bustago/yolo11n.engine \
    --server http://localhost:5000 --station-id DEMO01 \
    --post-interval 10 --debug
# debug 창에 카메라 + 세로 라인 두 개 표시되면 성공
```

### 3.5 노트북 브라우저에서 대시보드 확인
```
http://<JETSON_IP>:5000/admin/
```
→ 정류장 필터 = **DEMO01** 선택
→ 이벤트 피드 + 시연 제어 패널 표시 확인
→ `[🚶 IN +1]` 클릭 → 카드 플래시 + 피드 1건 추가

> 여기까지 잘 되면 **시연 본체 동작 확인 완료**. Pi 없이도 노트북 대체로 시연 가능.

## Phase 4 — Pi 키오스크 설치 (선택, 60분)

> **참조:** `HW_설치_가이드_Part2_Pi_통합테스트.md`
> Pi 안 쓰고 노트북 키오스크로 대체할 거면 Skip.

### 4.1 Pi OS 플래싱 + 초기 부팅
- Raspberry Pi Imager → OS Bookworm/Trixie (Desktop) → SD 카드 플래싱
- 호스트명 `bustago-kiosk` 또는 `amoo-rp`, WiFi/SSH 사전 설정
- 부팅 후 `ssh amoo_rp@amoo-rp.local`

### 4.2 7" 터치 디스플레이 연결
- DSI 리본 케이블 + 5V 점퍼 → Pi 보드
- 부팅 시 자동 인식 (Bookworm 이상)

### 4.3 Chromium 키오스크 패키지 설치
```bash
sudo apt update
sudo apt install -y chromium    # Bookworm/Trixie. Bullseye 이하는 chromium-browser
```

### 4.4 키오스크 systemd 서비스 등록
**참조 문서 §3.1**의 서비스 파일 그대로 사용 — `ExecStart=` 끝의 URL만 현장 Jetson IP로 변경:
```ini
ExecStart=/usr/bin/chromium --kiosk ... http://<JETSON_IP>:5000/student/index.html
```

```bash
sudo systemctl daemon-reload
sudo systemctl enable bustago-kiosk.service
sudo systemctl start bustago-kiosk.service
sudo systemctl status bustago-kiosk.service
```

### 4.5 Pi↔Jetson 연결 확인
```bash
# Pi에서
ping -c 4 <JETSON_IP>
curl -I http://<JETSON_IP>:5000/student/index.html
# → 200 OK
```
키오스크 화면에 광주대 정류장 PWA가 전체화면으로 표시되면 성공.

## 자주 발생하는 시연 현장 트러블

| 증상 | 원인 / 즉시 대응 |
|---|---|
| Jetson IP가 매번 바뀜 | 공유기에서 MAC 기반 고정 IP 할당, 안 되면 시작 전 `ip addr` 확인 후 Pi 서비스 파일 + 대시보드 URL 갱신 |
| counter.py가 `yolo11n.engine` 못 찾음 | `~/bustago/yolo11n.engine` 절대경로 지정 — `hardware/` 폴더에 없을 수 있음 |
| 대시보드 드롭다운에 "시연용 정류장" 없음 | DB 초기화 안 됨 — Phase 2.6 재실행 |
| 대시보드 지도 자리에 "키 필요" 박스만 뜸 | 카카오 키 미입력(Phase 2.7.2) 또는 도메인 미등록(2.7.3). **IP 바뀌면 도메인 재등록** 필수. 지도 외 대시보드는 정상이므로 시연엔 비치명적 |
| 카드 변하는데 이벤트 피드 비어있음 | SQLite id NULL 버그 (`5d2fd67` 미반영) — `git pull` + Phase 2.6 |
| Pi가 학생 화면 못 띄움 | Jetson IP 잘못된 것. `sudo systemctl status bustago-kiosk` 로그 확인 |
| 사람 통과했는데 카운트 0 | 라인 방향 확인 (IN 우→좌). 카메라 위치 조정 또는 `--in-line` 비율 조정 |
| TensorRT `.engine` 로드 실패 | 다른 기기에서 가져온 엔진 — Phase 2.5로 현재 기기에서 재생성 |
| 갑자기 모두 멈춤 | 전원 케이블·USB 케이블 확인. 우선순위: Jetson 전원 → 백엔드 프로세스 → counter.py 프로세스 |
