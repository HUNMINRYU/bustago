# 시연 대시보드 적용 가이드 — 사용자 액션 순서

> **목적:** `5b809b9` 시점에 머지된 시연용 카운팅 대시보드(DEMO01 정류장 + 이벤트 기반 + 백업 버튼)를 Jetson/노트북에 적용하고 동작을 확인하는 절차.
> **대상:** 운영자 본인. 시연·리허설 직전에 펼쳐놓고 따라간다.
> **연관 문서:** `운영_명령어_가이드_Jetson_Pi.md` (일반 운영), `docs/superpowers/specs/2026-05-30-demo-counting-dashboard-design.md` (설계)

## 1️⃣ Jetson에 최신 코드 동기화 (Jetson 터미널)
```bash
ssh amoo@172.30.1.75
cd ~/bustago
git checkout develop && git pull origin develop
git log --oneline -3   # 5b809b9 가 최상단인지 확인
```

## 2️⃣ Jetson DB 재초기화 (SQLite 자동증가 픽스 반영)
```bash
cd ~/bustago
rm -f backend/bustago.db
python3 -c "from backend.models.db import init_db; init_db()"
# 확인 (sqlite3 있을 때만):
# sqlite3 backend/bustago.db "SELECT ars_no FROM stations WHERE ars_no='DEMO01';"
```
> ⚠️ **이 단계 안 하면** `crowd_counts.id`가 계속 NULL이고 `/recent` 이벤트 피드가 안 돕니다.
> 이전 시연 데이터를 보존하고 싶다면 사전에 백업 후 진행 (`cp backend/bustago.db ~/bustago_db_$(date +%F).bak`).

## 3️⃣ 백엔드 기동 (Jetson 터미널 ①)
```bash
cd ~/bustago
python3 -m backend.app
# "Running on http://0.0.0.0:5000" 뜨면 OK. 켜둔 채로.
```

## 4️⃣ AI 카운팅 기동 — `DEMO01` 모드 (Jetson 터미널 ②, 새 SSH)
```bash
cd ~/bustago/hardware
python3 counter.py \
    --camera 0 \
    --model ~/bustago/yolo11n.engine \
    --server http://localhost:5000 \
    --station-id DEMO01 \
    --post-interval 10 \
    --debug
```
> 핵심: `--station-id`를 **`DEMO01`** 로. INS01 아닙니다.

## 5️⃣ 관리자 대시보드 열기 (노트북 브라우저)
```
http://172.30.1.75:5000/admin/
```
→ 정류장 필터 드롭다운에서 **`시연용 정류장`** (DEMO01) 선택
→ 화면 변화 확인:
- 상단 카운팅 카드 (대기 / IN / BOARD)
- 그 아래 **`최근 이벤트 LIVE`** 패널 새로 표시
- 그 아래 **`시연 제어`** 패널 (IN+1 / BOARD+1 / 리셋 버튼) 표시

→ 다른 정류장(INS01 등) 선택 시 두 패널이 자동으로 숨겨지는지 확인

## 6️⃣ 백업 버튼 동작 테스트 (카메라 없이도 됨)
대시보드에서 순서대로:
1. `[↺ 리셋]` 클릭 → 확인 → 0/0/0
2. `[🚶 IN +1]` 클릭 → **2초 안에** 카드 IN/대기 녹색 플래시 + 이벤트 피드에 `🚶 IN +1 (대기 1명)`
3. `[🚌 BOARD +1]` 클릭 → 카드 BOARD/대기 플래시 + 피드 추가
4. `[↺ 리셋]` → 0/0/0 복귀

## 7️⃣ 실제 카메라 통합 검증
1. Jetson debug 창에서 IN/BOARD 세로 라인 위치 확인 (IN `x=0.7` 오른쪽, BOARD `x=0.3` 왼쪽)
2. **사람 1명이 카메라 앞 우→좌 통과** → 3초 이내 카드/피드 반응
3. 사람이 BOARD 라인까지 더 진행 → BOARD 카운트 반응
4. 안 잡히면 즉시 백업 버튼(`IN +1` / `BOARD +1`) 클릭

## 8️⃣ 시연 사이 리셋 (반복 리허설)
1. 대시보드 `[↺ 리셋]` 클릭 → 확인
2. Jetson 터미널 ②: `Ctrl+C` → `↑ Enter` (counter.py 재시작)
3. 약 5초 후 0/0/0 → 다음 시연 준비 완료

> 리셋은 DB만 비웁니다. counter.py 메모리의 누적 카운터를 0으로 돌리려면 **반드시 재시작**해야 합니다.

## 막힐 수 있는 지점 & 대응

| 증상 | 원인 / 대응 |
|---|---|
| 드롭다운에 "시연용 정류장" 안 보임 | 2️⃣ DB 재초기화 안 됨 — 다시 실행 |
| 카드는 변하는데 이벤트 피드 비어있음 | 2️⃣ db.py 픽스 누락 → `git pull` 다시 + DB 재초기화 |
| Jetson 미연결로 표시 | 4️⃣ counter.py 안 떠있거나 `--station-id`가 DEMO01 아님 |
| `yolo11n.engine 없음` 에러 | `--model ~/bustago/yolo11n.engine` 전체 경로인지 확인 |
| 카드 플래시 안 됨 | 브라우저 강제 새로고침 (`Ctrl+Shift+R`) — CSS 캐시 |
| `[BOARD +1]` 눌렀더니 400 에러 | 대기 0인데 탑승 불가 — 먼저 `[IN +1]` 누름 |
| `INS01에서 reset 호출 → 400` | 정상 동작 — DEMO01만 화이트리스트. 실제 운영 데이터 보호 |

## 변경된 동작 요약 (참고)

| 항목 | 기존 | 신규(`5b809b9` 이후) |
|---|---|---|
| 대시보드 폴링 | 10초 | **2초** (DEMO01 + INS01 공통) |
| counter.py POST | 10초 주기 | **이벤트 즉시** + 10초 heartbeat |
| 카드 숫자 변경 표시 | 즉시 갱신 | **녹색 플래시 + 살짝 확대** (0.6초) |
| 이벤트 피드 | 없음 | DEMO01 선택 시 최근 5건 표시 |
| 백업 버튼 | 없음 | DEMO01 선택 시 IN+1/BOARD+1/리셋 |
| DEMO 격리 | — | `/event`·`/reset`·`/recent`가 station_id=DEMO01만 허용 |
| SQLite id 자동증가 | NULL(잠재 버그) | **수정됨** (`INTEGER PRIMARY KEY`) |

## 시연 종료 후

1. Jetson 터미널 ②: `Ctrl+C` (counter.py 종료)
2. Jetson 터미널 ①: `Ctrl+C` (백엔드 종료) — 다른 운영 모드로 전환할 거면 켜둠
3. 대시보드 닫기 또는 정류장 필터를 INS01로 되돌림 (정상 운영 모드 복귀)
4. (선택) DEMO01 잔여 데이터 정리:
   ```bash
   curl -X POST http://localhost:5000/api/crowd-count/reset \
        -H "Content-Type: application/json" -d '{"station_id":"DEMO01"}'
   ```
