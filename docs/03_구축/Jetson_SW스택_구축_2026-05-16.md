# Jetson Orin Nano YOLO11 환경 구축 — 단계별 튜토리얼

- **작성일:** 2026-05-16
- **수행자:** 류훈민
- **대상:** JetPack 6.2 (L4T R36.5)가 깔린 새 Jetson Orin Nano Devkit
- **소요 시간:** 약 1시간 30분 (네트워크 속도 양호 기준)
- **목표:** USB 웹캠으로 `counter.py`(YOLO11 + DeepSORT)가 실시간 동작하는 상태까지 만들기
- **결과:** ✅ 35 FPS 단독 추론 / 8.2 FPS 디버그 창 + 라인 + 트래킹 모두 정상 동작

## 0. 이 문서의 사용법

처음 Jetson을 받은 사람이 모니터·키보드·USB 웹캠을 연결한 직후부터 따라할 수 있도록 작성했습니다. 모든 명령은 **사용자 홈 디렉토리에서** 실행한다고 가정합니다.

**각 단계는 다음 구조로 되어 있습니다:**
- 왜 이걸 하는지
- 실행할 명령
- 기대 출력
- 막혔을 때 우회 방법

명령은 그대로 복사해 붙여넣어도 동작하도록 한 줄 형태로 정리했습니다. 들여쓰기가 포함된 Python 인라인 명령은 셸이 에러를 내므로 주의하세요.

## 1. 사전 확인 (모니터/네트워크/USB 웹캠 연결)

### 1.1 Jetson 부팅 직후 단말 열기

데스크탑 좌상단 `Activities` → `Terminal` 클릭. 또는 `Ctrl+Alt+T`.

### 1.2 인터넷 연결 확인

```bash
ping -c 2 8.8.8.8
```

기대: 두 줄 모두 응답. 응답 없으면 Wi-Fi/이더넷 연결 먼저 해결.

### 1.3 USB 웹캠 인식 확인

USB 웹캠을 Jetson USB 포트(가급적 본체에 직결)에 연결한 뒤:

```bash
ls /dev/video*
```

기대: `/dev/video0 /dev/video1` (UVC 표준 웹캠은 영상/메타데이터 2개 노드 생성).

**안 보이면:** 다른 USB 포트로 옮기고 `dmesg | tail -20` 으로 인식 로그 확인.

## 2. OpenCV 설치 + 카메라 1프레임 캡처 테스트

### 2.1 시스템 OpenCV 설치

JetPack에는 보통 들어있지만 빠져 있을 수 있어 명시적으로 설치합니다. **pip로 깔지 말고 apt로 깔아야 합니다** (시스템 OpenCV는 numpy 1.x 호환 + Jetson용 빌드).

```bash
sudo apt update
sudo apt install -y python3-opencv
```

설치 확인:
```bash
python3 -c "import cv2; print('cv2:', cv2.__version__, '@', cv2.__file__)"
```

기대 출력:
```
cv2: 4.5.4 @ /usr/lib/python3/dist-packages/cv2.cpython-310-aarch64-linux-gnu.so
```

### 2.2 카메라 1프레임 캡처

```bash
python3 -c "import cv2; cap=cv2.VideoCapture(0); ret,frame=cap.read(); print('Camera OK:', ret, frame.shape if ret else 'FAIL'); cap.release()"
```

기대 출력:
```
[ WARN:0] global ./modules/videoio/src/cap_gstreamer.cpp ...
Camera OK: True (480, 640, 3)
```

GStreamer 경고는 무해(V4L2 프로빙 메시지). `Camera OK: True (480, 640, 3)` 이면 통과.

**`True` 안 나오는 경우** — 카메라 인덱스를 1로 시도:
```bash
python3 -c "import cv2; cap=cv2.VideoCapture(1); ret,frame=cap.read(); print('Camera OK:', ret, frame.shape if ret else 'FAIL'); cap.release()"
```

## 3. CUDA 환경변수 설정

### 3.1 CUDA 설치 위치 확인

```bash
ls -d /usr/local/cuda*
```

기대: `/usr/local/cuda  /usr/local/cuda-12  /usr/local/cuda-12.6` (JetPack 6.2 기준).

### 3.2 PATH·LD_LIBRARY_PATH 추가

JetPack은 CUDA를 설치하지만 환경변수는 자동 추가하지 않습니다. `~/.bashrc`에 한 번 적어두면 영구 적용됩니다.

```bash
echo 'export PATH=/usr/local/cuda/bin:$PATH' >> ~/.bashrc
echo 'export LD_LIBRARY_PATH=/usr/local/cuda-12.6/targets/aarch64-linux/lib:/usr/lib/aarch64-linux-gnu:/usr/local/cuda/lib64:$LD_LIBRARY_PATH' >> ~/.bashrc
source ~/.bashrc
```

확인:
```bash
nvcc --version
```

기대 출력:
```
Cuda compilation tools, release 12.6, V12.6.68
```

**`command not found`가 나와도 무시 가능** — `nvcc`는 컴파일러라 PyTorch 추론에는 필요 없습니다. `libcudart`(런타임)만 LD_LIBRARY_PATH로 잡아두면 됩니다.

## 4. PyTorch (Jetson 전용 CUDA 빌드) 설치

### 4.1 왜 일반 pip torch를 쓰면 안 되는가

- 일반 `pip install torch`는 ARM aarch64에서 CPU 빌드만 제공
- Jetson GPU를 쓰려면 NVIDIA가 직접 빌드한 wheel을 받아야 함
- `pypi.jetson-ai-lab.dev`(외부 미러)는 DNS 해석이 안 될 수 있음

### 4.2 NVIDIA 공식 redist에서 wheel 목록 보기

```bash
curl -sL https://developer.download.nvidia.com/compute/redist/jp/v60/pytorch/ | grep -oE 'torch-[^"]+cp310[^"]+\.whl' | head -5
```

**중요:** `curl`에 반드시 `-L` 옵션을 줘야 합니다. NVIDIA 서버가 307 리다이렉트로 응답하기 때문에 `-L` 없으면 빈 결과가 나옵니다.

기대 출력 (예시):
```
torch-2.4.0a0+07cecf4168.nv24.05.14710581-cp310-cp310-linux_aarch64.whl
torch-2.4.0a0+3bcc3cddb5.nv24.07.16234504-cp310-cp310-linux_aarch64.whl
torch-2.4.0a0+f70bd71a48.nv24.06.15634931-cp310-cp310-linux_aarch64.whl
```

**가장 최신 빌드(nv24.07 또는 nv24.08)** 를 선택합니다. 이번 작업에서는 nv24.08 wheel을 사용했습니다.

### 4.3 시스템 라이브러리 + Wheel 설치

```bash
sudo apt install -y libopenblas-base libopenmpi-dev libomp-dev
cd ~
wget https://developer.download.nvidia.com/compute/redist/jp/v60/pytorch/torch-2.5.0a0+872d972e41.nv24.08-cp310-cp310-linux_aarch64.whl
pip3 install ./torch-2.5.0a0+872d972e41.nv24.08-cp310-cp310-linux_aarch64.whl
```

`pip3` 가 사용자 디렉토리(`~/.local/`)에 설치한다는 경고는 정상입니다.

### 4.4 cuDNN 8 추가 설치 (중요)

NVIDIA의 PyTorch nv24.08 빌드는 cuDNN 8용입니다. JetPack 6.2는 기본으로 cuDNN 9가 깔리므로 **cuDNN 8을 별도로 설치**해야 합니다 (공존 가능).

```bash
sudo apt install -y libcudnn8
```

### 4.5 PyTorch CUDA 검증

```bash
python3 -c "import torch; print('torch:', torch.__version__, '| CUDA:', torch.cuda.is_available(), '| device:', torch.cuda.get_device_name(0) if torch.cuda.is_available() else 'N/A')"
```

기대 출력:
```
torch: 2.5.0a0+872d972e41.nv24.08 | CUDA: True | device: Orin
```

**`CUDA: True` 가 나와야 다음 단계로 진행 가능합니다.**

**실패 시:**
- `libcudnn.so.8` 누락 → 4.4 단계 누락. `sudo apt install -y libcudnn8`
- `libnvToolsExt.so.1` 누락 → `sudo apt install -y cuda-nvtx-12-6`
- `libcublas.so` 누락 → LD_LIBRARY_PATH에 `/usr/local/cuda-12.6/targets/aarch64-linux/lib` 포함 확인

## 5. torchvision 소스 빌드

### 5.1 왜 pip torchvision은 안 되는가

- pip의 `torchvision==0.20.x`(ARM aarch64 wheel)는 PyTorch 공식 빌드의 ABI에 맞춰 만들어졌음
- 우리는 NVIDIA Jetson 빌드(nv24.08) PyTorch를 사용 중 → ABI가 다름
- 결과: `RuntimeError: operator torchvision::nms does not exist` 에러
- **소스에서 직접 빌드하는 것이 가장 안정적입니다**

### 5.2 빌드 의존성 + 소스 클론

```bash
sudo apt install -y libjpeg-dev zlib1g-dev libpng-dev
git clone --branch v0.20.1 --depth 1 https://github.com/pytorch/vision /tmp/torchvision
```

**torchvision 버전은 PyTorch 버전에 맞춰야 합니다:**
- torch 2.4.x ↔ torchvision 0.19.x
- torch 2.5.x ↔ torchvision 0.20.x
- torch 2.6.x ↔ torchvision 0.21.x

### 5.3 빌드 실행 (약 8~12분, Orin Nano 8GB 기준)

```bash
cd /tmp/torchvision
export BUILD_VERSION=0.20.1
python3 setup.py install --user 2>&1 | tail -30
```

**중간 출력은 매우 길지만 무시해도 됩니다.** `tail -30`이 종료 부근만 보여줍니다.

기대 마지막 줄:
```
Finished processing dependencies for torchvision==0.20.1
```

**`Killed` 메시지로 끝나면 RAM 부족.** 다른 프로그램 닫고 재시도. 또는 swap 파일 생성:
```bash
sudo fallocate -l 4G /swapfile && sudo chmod 600 /swapfile && sudo mkswap /swapfile && sudo swapon /swapfile
```

### 5.4 NMS 동작 검증 (핵심)

```bash
cat > /tmp/test_nms.py <<'EOF'
import torch, torchvision
from torchvision.ops import nms
boxes = torch.tensor([[0,0,10,10],[1,1,11,11],[50,50,60,60]], dtype=torch.float32)
scores = torch.tensor([0.9, 0.8, 0.7])
kept = nms(boxes, scores, 0.5)
print('torch:', torch.__version__)
print('vision:', torchvision.__version__)
print('nms kept:', kept.tolist())
EOF
python3 /tmp/test_nms.py
```

기대 출력:
```
torch: 2.5.0a0+872d972e41.nv24.08
vision: 0.20.1
nms kept: [0, 2]
```

`nms kept: [0, 2]` 가 나오면 CUDA NMS 연산자가 정상 등록된 것 → 통과.

## 7. NumPy 다운그레이드 + opencv-python 정리

### 7.1 왜 NumPy 2.x를 못 쓰는가

- ultralytics 의존성으로 `polars`가 깔리면서 `numpy 2.2.6`으로 자동 업그레이드됨
- NVIDIA의 PyTorch nv24.08은 NumPy 1.x ABI로 빌드됨
- 둘 사이에 경고가 뜨고, 추론 중 crash 가능성 있음

### 7.2 NumPy 1.26으로 다운그레이드

```bash
pip3 install --user "numpy<2" --force-reinstall
```

확인:
```bash
python3 -c "import numpy; print('numpy:', numpy.__version__)"
```

기대: `numpy: 1.26.4`

### 7.3 opencv-python 충돌 제거

ultralytics는 `opencv-python>=4.6.0`을 의존성으로 추가하는데, 최신 4.13은 numpy>=2를 요구해서 충돌합니다. **이미 시스템 OpenCV(2.1단계에서 설치)가 있으므로 pip 버전은 제거**합니다.

```bash
pip3 uninstall -y opencv-python
python3 -c "import cv2; print('cv2:', cv2.__version__, '@', cv2.__file__)"
```

기대: `cv2: 4.5.4 @ /usr/lib/python3/dist-packages/cv2...` (시스템 경로).

### 7.4 풀스택 통합 검증 (체크리스트)

```bash
python3 -c "import numpy, torch, torchvision, cv2; from torchvision.ops import nms; print('numpy:', numpy.__version__, '| torch:', torch.__version__, '| vision:', torchvision.__version__, '| CUDA:', torch.cuda.is_available(), '| cv2:', cv2.__version__)"
```

기대 출력 (한 줄, **NumPy 경고 없음**):
```
numpy: 1.26.4 | torch: 2.5.0a0+872d972e41.nv24.08 | vision: 0.20.1 | CUDA: True | cv2: 4.5.4
```

경고가 같이 떠도 동작은 합니다만, 깨끗하게 한 줄만 나오는 것이 이상적입니다.

## 9. YOLO 단독 추론 테스트

### 9.1 한 줄 테스트 (모델 자동 다운로드 + 카메라 추론)

```bash
python3 -c "from ultralytics import YOLO; m = YOLO('yolo11n.pt'); r = m.predict(source=0, save=False, show=False, max_det=10, verbose=True); print('Detections:', len(r[0].boxes), '| classes:', r[0].boxes.cls.tolist() if len(r[0].boxes) else [])"
```

첫 실행 시 `yolo11n.pt` (약 5.4MB) 가 자동 다운로드됩니다.

기대 출력 (스트리밍, 연속 출력):
```
0: 480x640 1 person, 27.8ms
0: 480x640 (no detections), 28.5ms
0: 480x640 1 person, 27.9ms
...
```

**판정 기준:**

| 추론 시간 | 환산 FPS | 평가 |
|---|---|---|
| `< 30ms` | ≥ 33 FPS | ✅ 시연 충분 (이번 결과: 28ms) |
| `30~70ms` | 14~33 FPS | ⚠️ TensorRT 변환 권장 |
| `> 100ms` | < 10 FPS | ❌ GPU 미가속 의심 |

종료: `Ctrl+C`.

## 10. counter.py 실시간 디버그 실행

### 10.1 실행 명령

```bash
cd ~/bustago/hardware
python3 counter.py --camera 0 --model yolo11n.pt --debug
```

### 10.2 기대 동작

OpenCV 창(`BUSTAGO Counter`)이 뜨고:
- 사람마다 노란색 bounding box + tracking ID
- 화면에 두 개의 가로선
  - **BOARD LINE (녹색, 위쪽)** — 버스 탑승 인식선 (default: 화면 위에서 30%)
  - **IN LINE (파란색, 아래쪽)** — 정류장 진입 인식선 (default: 화면 위에서 70%)
- 좌상단에 `Waiting`(현재 대기자), `FPS`
- 좌하단/상단에 `IN LINE (entered: 0)`, `BOARD LINE (boarded: 0)` 카운터

종료: 창에 포커스 두고 `q` 키, 또는 터미널에서 `Ctrl+C`.

### 10.3 정상 로그 vs 무시해도 되는 로그

**정상:**
- `Waiting`, `FPS` 표시
- 사람 입장 시 bounding box 따라옴

**무시 OK (백엔드 미연결 시):**
```
[WARN] POST failed: http://localhost:5000/api/crowd-count - Connection refused
```
백엔드 Flask 서버가 안 떠있어서 그런 것. 시각 검증 단계에서는 정상.

### 10.4 카메라 각도와 라인 위치 튜닝

**시연에서는 카메라가 천장 2~2.5m에서 사선 하방을 봐야** Line Crossing 로직이 의미있게 동작합니다(보행자가 위에서 아래로 라인을 건너야 IN/BOARD 카운트가 증가).

마운트 위치 확정 후 라인 위치 조정:
```bash
python3 counter.py --camera 0 --model yolo11n.pt --debug --in-line 0.7 --board-line 0.3
```
- `--in-line 0.7`: 화면 위에서 70% 위치
- `--board-line 0.3`: 화면 위에서 30% 위치

## 12. 흔한 함정 모음

### 12.1 셸 들여쓰기 에러
```python
python3 -c "
  import torch
  ...
"
# → IndentationError
```
**해결:** Python 인라인 명령은 한 줄로(`;`로 구분), 또는 임시 파일로 저장해 실행.

### 12.2 DNS 해석 실패
- `pypi.jetson-ai-lab.dev`가 해석 안 됨 → NVIDIA 공식 redist 사용
- 다른 도메인도 모두 실패하면 `/etc/resolv.conf`에 `nameserver 8.8.8.8` 추가

### 12.3 curl 307 응답
- NVIDIA redist는 307 리다이렉트로 응답 → `-L` 옵션 필수

### 12.4 ABI 미스매치
- pip torchvision은 NVIDIA torch와 ABI 다름 → **소스 빌드 필수**
- numpy 2.x는 NVIDIA torch와 ABI 다름 → **numpy<2 고정**

### 12.5 opencv-python 충돌
- ultralytics가 pip opencv-python을 자동 설치하면서 numpy>=2 요구 → 제거하고 시스템 opencv 사용

### 12.6 cuDNN 8 vs 9
- JetPack 6.2 기본은 cuDNN 9. NVIDIA torch nv24.08은 cuDNN 8용 → `libcudnn8` 별도 설치

### TensorRT 변환 (선택)

성능 마진을 더 확보하고 싶으면:
```bash
yolo export model=yolo11n.pt format=engine half=True device=0
# → yolo11n.engine 파일 생성 (FP16, GPU 최적화)
python3 counter.py --camera 0 --model yolo11n.engine --debug
```

기대: 단독 추론 ~10ms (100 FPS), debug 모드 약 20~25 FPS.

### 헤드리스 + 백엔드 연동 (실배포 형태)

```bash
# 백엔드 서버 IP 지정, debug 끔, 5초마다 POST
python3 counter.py --camera 0 --model yolo11n.pt \
  --server http://SERVER_IP:5000/api/crowd-count \
  --station-id INS01 --post-interval 5
```
