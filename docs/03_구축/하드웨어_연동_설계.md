## 1. 개요

### 1.1 목적

광주대학교 캠퍼스 내 버스 정류장에 Raspberry Pi 기반 현장 디스플레이를 설치하여, BUSTAGO 시스템의 혼잡도 예측 정보를 실시간으로 학생 및 교직원에게 제공한다.

### 1.2 대상 정류장

| 정류장 | 위치 | 용도 | 우선순위 |
|--------|------|------|----------|
| 인성관 셔틀 정류장 | 인성관 앞 | 교내 셔틀버스 | 1순위 (시범 설치) |
| 정문 시내버스 정류장 | 정문 | 시내버스 | 2순위 |

### 1.3 디바이스 구성

- **메인 보드:** Raspberry Pi 4 Model B (4GB RAM)
- **디스플레이:** 7인치 터치스크린 (800x480, DSI 연결) 또는 10인치 IPS (1280x800, HDMI)
- **카메라:** Pi Camera Module v2 (8MP) -- 향후 YOLOv8 인원 카운팅용
- **저장장치:** 64GB microSD (High Endurance, A2)

### 1.4 현재 시스템 상태

| 항목 | 상태 | 비고 |
|------|------|------|
| ML 모델 | 완료 | RandomForest, CV 0.9962 |
| Backend API | 완료 | Flask, Prediction Cache 23ms 응답 |
| Student PWA | 완료 | Service Worker 오프라인 지원 |
| Admin Dashboard | 완료 | 60초 자동 갱신 구현 |
| Rate Limiting | 완료 | Flask-Limiter 전 엔드포인트 적용 |

## 2. 시스템 아키텍처

### 2.1 전체 구성도

```
┌─────────────────────────────────────────────────────────┐
│                    캠퍼스 정류장                           │
│                                                         │
│  [Pi Camera v2] ──→ [Raspberry Pi 4] ──WiFi──→ [BUSTAGO Backend API]
│                          │                        │
│                          ↓                        ↓
│                   [7인치 디스플레이]          [MySQL / SQLite]
│                   (혼잡도 + 추천)            [ML predict.py]
│                                                         │
└─────────────────────────────────────────────────────────┘
```

### 2.2 데이터 흐름

```
1. Chromium Kiosk → GET http://SERVER_IP/api/predict?station_id=INS01&hour=9&weekday=1
2. nginx reverse proxy → Backend:5000 → LRU TTL Cache 확인 → Cache miss 시 predict.py 호출
3. 응답 JSON → Frontend 렌더링 (혼잡도 레벨 + 색상 표시 + 추천 정보)
4. 60초 후 자동 갱신 (기존 dashboard.js REFRESH_MS=60000 활용)
```

### 2.3 향후 확장 (카메라 연동)

```
[Pi Camera] → OpenCV 캡처 (5초 간격)
     ↓
[YOLOv8-nano] → 인원 카운팅
     ↓
POST /api/crowd-count → Backend 실측 데이터 저장
     ↓
ML 모델 재학습 피드백 루프
```

## 4. 소프트웨어 스택

### 4.1 OS 및 기본 환경

| 계층 | 기술 | 버전 | 비고 |
|------|------|------|------|
| OS | Raspberry Pi OS Lite | 64-bit (Bookworm) | GUI 없는 경량 버전 |
| Display Server | Wayland (labwc) 또는 X11 | -- | kiosk 모드 전용 |
| 브라우저 | Chromium | 최신 | `--kiosk` 모드 |
| Python | 3.11+ | -- | 카메라/유틸리티 스크립트용 |

### 4.2 Kiosk 모드 구성

Chromium을 전체화면 키오스크로 실행하여 Student PWA를 표시한다.

```bash
# /etc/xdg/autostart/kiosk.desktop 또는 systemd service
chromium-browser \
  --kiosk \
  --noerrdialogs \
  --disable-infobars \
  --disable-session-crashed-bubble \
  --app=http://<SERVER_IP>/student/index.html
```

### 4.3 자동 갱신 전략

기존 구현을 그대로 활용한다:

- **Admin Dashboard:** `REFRESH_MS = 60000` (60초) -- `dashboard.js` 에 이미 구현
- **Student PWA:** `app.js` 에서 동일하게 주기적 fetch 구현 가능
- **추가 개발 불필요:** 기존 Frontend가 자동 갱신을 지원하므로 Raspberry Pi에서는 브라우저만 띄우면 된다

### 4.4 카메라 소프트웨어 (향후)

```
Phase 2에서 구현 예정:
- libcamera (Pi Camera 제어)
- OpenCV 4.x (프레임 캡처)
- YOLOv8-nano (Ultralytics, ONNX Runtime)
- 인원 카운팅 결과를 Backend API로 POST
```

## 5. 설치 절차

### 5.1 OS 설치 및 초기 설정

```bash
# 1) Raspberry Pi Imager로 microSD에 OS 굽기
#    - Raspberry Pi OS Lite (64-bit) 선택
#    - 고급 설정에서 WiFi, SSH, 사용자 계정 미리 설정

# 2) 첫 부팅 후 SSH 접속
ssh bustago@<PI_IP>

# 3) 시스템 업데이트
sudo apt update && sudo apt upgrade -y

# 4) 필수 패키지 설치
sudo apt install -y chromium-browser xserver-xorg xinit unclutter
```

### 5.2 디스플레이 설정

```bash
# DSI 7인치 터치스크린 (자동 인식, 별도 설정 불필요)
# HDMI 디스플레이의 경우:
sudo nano /boot/firmware/config.txt

# 추가 내용:
# hdmi_force_hotplug=1
# hdmi_group=2
# hdmi_mode=87
# hdmi_cvt 800 480 60 6 0 0 0  (7인치 800x480 기준)
```

### 5.3 Kiosk 모드 자동 시작

```bash
# systemd 서비스 파일 생성
sudo tee /etc/systemd/system/bustago-kiosk.service << 'EOF'
[Unit]
Description=BUSTAGO Kiosk Display
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
User=bustago
Environment=DISPLAY=:0
ExecStartPre=/usr/bin/xinit -- :0 -nocursor &
ExecStart=/usr/bin/chromium-browser --kiosk --noerrdialogs --disable-infobars --disable-session-crashed-bubble --app=http://SERVER_IP/student/index.html
Restart=on-failure
RestartSec=10

[Install]
WantedBy=multi-user.target
EOF

sudo systemctl enable bustago-kiosk.service
```

### 5.4 화면 보호기 비활성화

```bash
# X11 화면 보호기/절전 끄기
sudo tee /etc/X11/xorg.conf.d/10-blanking.conf << 'EOF'
Section "ServerFlags"
    Option "BlankTime" "0"
    Option "StandbyTime" "0"
    Option "SuspendTime" "0"
    Option "OffTime" "0"
EndSection
EOF
```

### 5.5 Backend API 연결 확인

```bash
# API 헬스체크 (Docker nginx 경유)
curl http://<SERVER_IP>/api/health

# 예측 API 테스트
curl "http://<SERVER_IP>/api/predict?station_id=INS01&hour=9&weekday=1"

# 정상 응답 예시:
# {"station_id":"INS01","hour":9,"predicted_level":"보통","color":"#FFA500",...}
```

## 6. 네트워크 구성

### 6.1 캠퍼스 WiFi 연결

```bash
# nmcli를 사용한 WiFi 연결
sudo nmcli device wifi connect "GU-Campus-WiFi" password "비밀번호"

# 고정 IP 설정 (권장)
sudo nmcli connection modify "GU-Campus-WiFi" \
  ipv4.method manual \
  ipv4.addresses 192.168.1.101/24 \
  ipv4.gateway 192.168.1.1 \
  ipv4.dns 8.8.8.8
```

### 6.2 네트워크 토폴로지

```
[Raspberry Pi #1 (인성관)]  ──WiFi──┐
                                     ├──→ [캠퍼스 AP] ──→ [BUSTAGO Server (Docker)]
[Raspberry Pi #2 (정문)]    ──WiFi──┘          nginx:80 → backend:5000
```

### 6.3 오프라인 Fallback

기존 구현된 Service Worker(`frontend/student/service-worker.js`)가 오프라인 대응을 처리한다:

- **캐시 전략:** 네트워크 우선, 실패 시 캐시된 마지막 데이터 표시
- **오프라인 UI:** "네트워크 연결 확인 중..." 안내 메시지 표시
- **자동 복구:** 네트워크 복구 시 자동으로 최신 데이터 갱신

### 6.4 네트워크 안정성 모니터링

```bash
# WiFi 자동 재연결 cron (5분마다)
*/5 * * * * /usr/bin/ping -c 1 192.168.1.10 > /dev/null 2>&1 || sudo systemctl restart NetworkManager
```

## 8. 리스크 및 대응

### 8.1 리스크 매트릭스

| # | 리스크 | 발생 가능성 | 영향도 | 대응 방안 | 현재 상태 |
|---|--------|-----------|--------|----------|----------|
| R1 | 캠퍼스 WiFi 불안정/끊김 | 높음 | 중간 | Service Worker 캐시 (이미 구현), WiFi 자동 재연결 cron | 대응 완료 |
| R2 | 전원 차단 (정전, 플러그 분리) | 중간 | 높음 | systemd 자동 시작, watchdog cron | 대응 예정 |
| R3 | SD카드 손상 (반복 쓰기) | 낮음 | 높음 | read-only rootfs 설정, 로그 tmpfs 전환 | 대응 예정 |
| R4 | API 과부하 (다수 Pi 동시 요청) | 낮음 | 중간 | Rate Limiting 이미 구현 (Flask-Limiter), Prediction Cache 23ms | 대응 완료 |
| R5 | 외부 환경 (비, 직사광선) | 중간 | 중간 | IP65 방수 케이스, 직사광선 차단 위치 선정 | 설치 시 확인 |
| R6 | 보안 (무단 접근, API 악용) | 낮음 | 높음 | API Rate Limiting + 입력 검증 이미 구현, Pi SSH 키 인증 전환 | 대응 완료 |

### 8.2 자동 복구 스크립트

```bash
#!/bin/bash
# /usr/local/bin/bustago-watchdog.sh
# Chromium 프로세스 확인, 죽었으면 재시작
if ! pgrep -x "chromium-browse" > /dev/null; then
    sudo systemctl restart bustago-kiosk.service
    logger "BUSTAGO: Kiosk 프로세스 재시작됨"
fi

# crontab에 등록
# */2 * * * * /usr/local/bin/bustago-watchdog.sh
```

### 8.3 SD카드 수명 보호

```bash
# /tmp를 tmpfs로 마운트하여 SD 쓰기 최소화
# /etc/fstab에 추가:
tmpfs /tmp tmpfs defaults,noatime,nosuid,size=100m 0 0
tmpfs /var/log tmpfs defaults,noatime,nosuid,size=50m 0 0
```

## 9. 참고 사항

### 9.1 기존 구현과의 연계점

| 기존 구현 | 파일 | 하드웨어 연동 시 활용 |
|-----------|------|---------------------|
| Student PWA | `frontend/student/index.html` | Kiosk 브라우저에 표시할 메인 화면 |
| Service Worker | `frontend/student/service-worker.js` | 오프라인 Fallback 처리 |
| Auto Refresh | `frontend/admin/dashboard.js` | 60초 자동 갱신 로직 참조 |
| API Health | `/api/health` | Pi 연결 상태 모니터링용 |
| Prediction Cache | Backend LRU TTL Cache | Pi 다수 연결 시에도 23ms 응답 보장 |
| Rate Limiting | Flask-Limiter | Pi 요청 빈도 제어 |

### 9.2 향후 확장 로드맵

1. **Phase 1 (현재):** Chromium Kiosk + 기존 PWA 표시
2. **Phase 2:** Pi Camera + YOLOv8-nano 인원 카운팅 PoC
3. **Phase 3:** 실측 데이터 기반 ML 모델 재학습 파이프라인
4. **Phase 4:** 다중 정류장 중앙 모니터링 (Admin Dashboard 확장)
