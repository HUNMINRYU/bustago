# BUSTAGO 하드웨어 연동 설계서

> **작성일:** 2026-04-02 (v2.0 전면 개정: 2026-04-10)  
> **작성자:** BUSTAGO 팀  
> **버전:** v2.0 — Jetson Orin Nano + Pi 4 역할 분리 구조, 카메라 1대 고 FPS 방식

---

## 1. 개요

### 1.1 목적

광주대학교 캠퍼스 내 버스 정류장에 **Jetson Orin Nano(AI 추론) + Raspberry Pi 4(키오스크 디스플레이)** 2보드 구조를 설치하여, BUSTAGO 시스템의 혼잡도 예측 정보를 실시간으로 제공하고, 카메라 기반 인원 카운팅으로 실측 데이터를 수집한다.

### 1.2 v1.x → v2.0 변경 근거

| 항목 | v1.x (Pi 4 Only) | v2.0 (Jetson + Pi 4) |
|------|-------------------|---------------------|
| AI 추론 | Pi 4 CPU, 2~5 FPS | **Jetson GPU, 25~40 FPS** |
| 카메라 | 3대 (성능 부족 보상) | **1대 (고 FPS로 충분)** |
| DeepSORT 트래킹 | 사실상 불가 (CPU) | **실시간 가능 (CUDA)** |
| 카운팅 정확도 | 시연 수준 | **실측(Ground Truth) 수준** |
| 키오스크 안정성 | AI 부하와 경합 | **독립 보드, 안정적** |
| 예산 | 75만원 (2정류장) | **79만원 (1정류장, 최대 성능)** |

### 1.3 대상 정류장

| 정류장 | 위치 | 용도 | 우선순위 |
|--------|------|------|----------|
| 인성관 셔틀 정류장 | 인성관 앞 | 교내 셔틀버스 | 1순위 (시범 설치) |
| 정문 시내버스 정류장 | 정문 | 시내버스 | 2순위 (예산 확보 시) |

### 1.4 디바이스 구성

| 역할 | 보드 | 담당 |
|------|------|------|
| **AI 추론** | NVIDIA Jetson Orin Nano 8GB | YOLOv8 + DeepSORT + 카메라 |
| **키오스크 디스플레이** | Raspberry Pi 4 4GB | Chromium Kiosk + PWA 표시 |

### 1.5 현재 시스템 상태

| 항목 | 상태 | 비고 |
|------|------|------|
| ML 모델 | 완료 | RandomForest, CV 0.9962 |
| Backend API | 완료 | Flask, Prediction Cache 23ms 응답 |
| Student PWA | 완료 | Service Worker 오프라인 지원 |
| Admin Dashboard | 완료 | 60초 자동 갱신, 도넛차트, 지도 |
| Rate Limiting | 완료 | Flask-Limiter 전 엔드포인트 적용 |
| Docker 배포 | 완료 | nginx:80 → backend:5000 프록시 |

## 2. 시스템 아키텍처

### 2.1 전체 구성도

```
┌─────────────────────────────────────────────────────────────────┐
│                    인성관 셔틀 정류장                               │
│                                                                 │
│  [Pi Camera v2]                                                 │
│       │ CSI                                                     │
│       ▼                                                         │
│  [Jetson Orin Nano 8GB] ─── WiFi ──→ [BUSTAGO Server (Docker)]  │
│   - YOLOv8-nano (25~40 FPS)              │                      │
│   - DeepSORT 실시간 트래킹                 │                      │
│   - Line Crossing 카운팅                   ▼                     │
│   - POST /api/crowd-count          [nginx:80 → backend:5000]   │
│                                    [SQLite / MySQL]             │
│  [Raspberry Pi 4 4GB] ──── WiFi ──→ [ML predict.py]            │
│       │                                                         │
│       ▼                                                         │
│  [7인치 DSI 터치스크린]                                           │
│   - Chromium Kiosk 모드                                          │
│   - Student PWA 표시                                             │
│   - 60초 자동 갱신                                                │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### 2.2 데이터 흐름

```
[키오스크 경로]
1. Pi 4 Chromium Kiosk → GET http://SERVER_IP/api/predict
2. nginx reverse proxy → Backend:5000 → LRU TTL Cache → predict.py
3. 응답 JSON → PWA 렌더링 (혼잡도 4단계 + 추천)
4. 60초 후 자동 갱신

[AI 카운팅 경로]
1. Pi Camera v2 → Jetson Orin Nano (CSI, 30 FPS 캡처)
2. YOLOv8-nano → 사람 bbox 탐지 (25~40 FPS)
3. DeepSORT → Track ID 부여 + 궤적 추적
4. Line Crossing → IN/OUT 카운트 갱신
5. 10초 간격 POST /api/crowd-count → Backend DB 저장
6. ML 모델 재학습 피드백 루프
```

### 2.3 보드 간 역할 분리

```
┌──────────────────────┐     ┌──────────────────────┐
│   Jetson Orin Nano   │     │   Raspberry Pi 4     │
│                      │     │                      │
│  [카메라 입력]        │     │  [디스플레이 출력]     │
│  [YOLOv8 추론]       │     │  [Chromium Kiosk]    │
│  [DeepSORT 트래킹]   │     │  [PWA 렌더링]        │
│  [카운팅 집계]        │     │  [Service Worker]    │
│  [API POST 전송]     │     │  [API GET 수신]      │
│                      │     │                      │
│  GPU: 1024 CUDA      │     │  GPU: 없음 (불필요)   │
│  AI 전용, 디스플레이 無│     │  디스플레이 전용      │
└──────────┬───────────┘     └──────────┬───────────┘
           │                            │
           └──── WiFi → Backend ────────┘
```

> **분리 이유:** Jetson에서 AI 추론과 Chromium을 동시 실행하면 GPU 메모리 경합 발생.  
> Pi 4는 Kiosk 전용으로 안정성 극대화, Jetson은 AI 전용으로 성능 극대화.

## 3. AI 인원 카운팅 설계

### 3.1 왜 카메라 1대로 충분한가

| 비교 | v1.x (Pi 4 + 3대) | v2.0 (Jetson + 1대) |
|------|-------------------|---------------------|
| FPS | 2~5 (CPU) | **25~40 (GPU)** |
| 트래킹 | 불가 → 중복 카운팅 | **DeepSORT 실시간** |
| 프레임 간 누락 | 빈번 (저 FPS) | **거의 없음 (고 FPS)** |
| 필요 카메라 수 | 3대 (보상용) | **1대 (충분)** |

고 FPS에서는 사람의 이동이 프레임 간 몇 픽셀 차이로만 나타나므로, DeepSORT의 IoU 매칭과 칼만 필터가 정확하게 동작한다.

### 3.2 카메라 배치

```
          [버스 정차 위치]
               │
    ═══════════╪═══════════  탑승 라인 (BOARD)
               │
         [대기 영역]
               │
    ═══════════╪═══════════  진입 라인 (IN)
               │
         [접근 통로]
               │
          ┌────┴────┐
          │ CAM-1   │  ← Pi Camera v2
          │ (상단)  │     높이 2.5~3m, 하향 45°
          └─────────┘     정류장 전체 조감
```

| 항목 | 설정 |
|------|------|
| 카메라 | Pi Camera v2 (8MP, CSI) |
| 설치 높이 | 2.5~3m (정류장 지붕 또는 폴) |
| 화각 | 하향 45° — 정류장 전체 커버 |
| 해상도 | 640×480 (추론 속도 최적화) |
| 캡처 FPS | 30 FPS (Jetson 처리 여유) |

### 3.3 중복 카운팅 방지 (DeepSORT)

**파이프라인:**

```
Pi Camera v2 (30 FPS)
     │
     ▼
[YOLOv8-nano] → 사람 bbox 추출 (25~40 FPS on Jetson GPU)
     │
     ▼
[DeepSORT 트래커]
  - IoU(겹침 영역) 매칭
  - Re-ID Feature 비교 (외형 128D 벡터)
  - 칼만 필터 위치 예측
     │
     ▼
[고유 Track ID 유지]
  Track #1: Person A (프레임 간 연속 추적)
  Track #2: Person B (프레임 간 연속 추적)
     │
     ▼
[Line Crossing 판정]
  - IN 라인 통과 (위→아래): 정류장 진입 +1
  - BOARD 라인 통과 (아래→위, 버스 도착 시): 탑승 +1
  - 동일 Track ID는 같은 라인을 재통과해도 재카운트 안 함
     │
     ▼
[현재 대기 인원 = 누적 IN - 누적 BOARD - 이탈]
     │
     ▼
POST /api/crowd-count (10초 간격)
```

### 3.4 기술 스택 (Jetson)

| 라이브러리 | 용도 | Jetson 최적화 |
|-----------|------|-------------|
| JetPack 6.x | Jetson OS + CUDA + TensorRT | 공식 SDK |
| YOLOv8-nano | 사람 객체 탐지 | **TensorRT FP16 가속** (25~40 FPS) |
| DeepSORT | 다중 객체 트래킹 | CUDA Re-ID 추출 |
| OpenCV 4.x (CUDA) | 프레임 캡처 + 전처리 | GPU 가속 리사이즈 |
| libcamera / V4L2 | Pi Camera v2 제어 | CSI 직접 연결 |

### 3.5 Jetson 카운팅 서비스

```bash
# /etc/systemd/system/bustago-counter.service
[Unit]
Description=BUSTAGO AI People Counter
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
User=bustago
WorkingDirectory=/home/bustago/counter
ExecStart=/usr/bin/python3 counter.py --camera 0 --model yolov8n.engine --server http://SERVER_IP/api/crowd-count
Restart=on-failure
RestartSec=10

[Install]
WantedBy=multi-user.target
```

## 5. 소프트웨어 스택

### 5.1 Pi 4 (키오스크)

| 계층 | 기술 | 비고 |
|------|------|------|

| 계층 | 기술 | 비고 |

### 5.3 Kiosk 모드 구성 (Pi 4)

```bash
chromium-browser \
  --kiosk \
  --noerrdialogs \
  --disable-infobars \
  --disable-session-crashed-bubble \
  --app=http://<SERVER_IP>/student/index.html
```

기존 구현을 그대로 활용:

## 6. 설치 절차

### 6.1 Pi 4 (키오스크) 설치

```bash
# 1) Pi Imager로 OS 굽기 (Pi OS Lite 64-bit, WiFi/SSH 사전 설정)
# 2) 첫 부팅 후 SSH 접속
ssh bustago@<PI_IP>

# 3) 업데이트 + 패키지 설치
sudo apt update && sudo apt upgrade -y
sudo apt install -y chromium-browser xserver-xorg xinit unclutter

# 4) Kiosk 서비스 등록
sudo tee /etc/systemd/system/bustago-kiosk.service << 'EOF'
[Unit]
Description=BUSTAGO Kiosk Display
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
User=bustago
Environment=DISPLAY=:0
ExecStartPre=/usr/bin/xinit -- :0 -nocursor &
ExecStart=/usr/bin/chromium-browser --kiosk --noerrdialogs --disable-infobars --disable-session-crashed-bubble --app=http://SERVER_IP/student/index.html
Restart=on-failure
RestartSec=10

[Install]
WantedBy=multi-user.target
EOF

sudo systemctl enable bustago-kiosk.service
```

### 6.2 Jetson Orin Nano (AI) 설치

```bash
# 1) NVIDIA SDK Manager로 JetPack 6.x 플래싱 (PC에서 USB 연결)
# 2) 첫 부팅 후 SSH 접속
ssh bustago@<JETSON_IP>

# 3) Python 환경 + AI 스택 설치
pip3 install ultralytics opencv-python-headless deep-sort-realtime

# 4) YOLOv8-nano → TensorRT 엔진 변환 (최초 1회)
python3 -c "
from ultralytics import YOLO
model = YOLO('yolov8n.pt')
model.export(format='engine', half=True)  # FP16 TensorRT
"

# 5) 카메라 테스트
python3 -c "
import cv2
cap = cv2.VideoCapture(0)
ret, frame = cap.read()
print(f'Camera OK: {frame.shape}' if ret else 'Camera FAIL')
cap.release()
"

# 6) 카운팅 서비스 등록
sudo systemctl enable bustago-counter.service
```

### 6.3 Backend API 연결 확인

```bash

curl http://<SERVER_IP>/api/health

# 예측 API 테스트
```

### 9.2 자동 복구

```bash
# Pi 4: Kiosk watchdog (2분마다)
*/2 * * * * pgrep -x "chromium-browse" > /dev/null || sudo systemctl restart bustago-kiosk.service

# Jetson: Counter watchdog (2분마다)
*/2 * * * * pgrep -f "counter.py" > /dev/null || sudo systemctl restart bustago-counter.service

# 양쪽: WiFi 자동 재연결 (5분마다)
*/5 * * * * /usr/bin/ping -c 1 192.168.1.10 > /dev/null 2>&1 || sudo systemctl restart NetworkManager
```

## 10. 참고 사항

### 10.1 기존 구현과의 연계점

| 기존 구현 | 파일 | 연동 방식 |
|-----------|------|----------|
| Student PWA | `frontend/student/index.html` | Pi 4 Kiosk에 표시 |
| Service Worker | `frontend/student/service-worker.js` | 오프라인 Fallback |
| Auto Refresh | `frontend/admin/dashboard.js` | 60초 자동 갱신 |
| Prediction Cache | Backend LRU TTL Cache | 23ms 응답 보장 |
| Rate Limiting | Flask-Limiter | 요청 빈도 제어 |
| Docker 배포 | `docker-compose.yml` | nginx:80 → backend:5000 |

### 10.2 신규 개발 필요 항목

| # | 항목 | 담당 보드 | 우선순위 |
