# AI 스킬 자율 진화 파이프라인: gstack 역할 구조 정의

## 1. 개요
이 문서는 자율 AI 스킬 진화 파이프라인에서 **`gstack`**이 담당하는 "역할 구조(Role Structure)"의 개념과 명세(Specification)를 정의합니다. 이 정의 문서는 이후 `harness` 환경에서의 평가 및 `autoresearch`에 의한 자율적인 스킬 진화의 기준점이 됩니다.

## 2. 파이프라인 컨텍스트 (Evolution Pipeline)
본 파이프라인은 생물학적 진화 모델의 메커니즘을 소프트웨어 스킬에 적용한 아키텍처입니다.

1. **`gstack` (역할 구조 / DNA)**: 에이전트가 특정 태스크를 해결하기 위해 가져야 할 권한, 프롬프트 특성, 실행 프로세스, 사용 도구를 정의합니다. 쉽게 말해 **"진화의 대상이 되는 설계도"**입니다.
2. **`harness` (테스트 환경 / Environment)**: `gstack`으로 정의된 스킬이 실제로 목표를 잘 달성하는지 평가하는 단위 테스트 혹은 E2E 벤치마크 런타임입니다. (Claude Code 영역에서 실행)
3. **`autoresearch` (자율 진화 / Evolution Loop)**: `harness`에서 반환된 성과 점수(예: 성공률, 속도, 비용 등)를 피드백으로 삼아 `gstack` 역할 구조를 프로그래밍적으로 수정하고 최적화합니다.

---

## 3. gstack 역할 구조(Role Structure)의 4대 구성 요소
`autoresearch`가 `gstack` 스킬을 효과적으로 진화시키기 위해서는 규칙적인 컴포넌트 구조가 필요합니다. `gstack`의 역할 구조는 기본적으로 마크다운(`SKILL.md`) 포맷을 따르며, 아래의 4가지 주요 계층으로 구성됩니다.

### 3.1. 메타데이터 구조 (Metadata & Tooling Constraints)
* **목적**: 스킬의 인터페이스와 제약 조건을 YAML 형태로 정의합니다.
* **구성요소**: 스킬 이름, 버전, 사용 목적 요약, 허용된 도구(`allowed-tools`) 목록.
* **진화적 의미**: 어떤 도구를 열어주고 닫을지에 대한 접근 제어(RBAC) 레이어로, `autoresearch`는 특정 작업에 불필요한 도구를 제거함으로써 환각(Hallucination)을 줄이는 방향으로 최적화할 수 있습니다.

### 3.2. 프리앰블 및 컨텍스트 로직 (Preamble & State Management)
* **목적**: 스킬이 실행되기 전에 요구되는 환경 설정 및 상태 초기화를 실행합니다.
* **구성요소**: 환경 변수 로드, 필수 바이너리 체크, 텔레메트리 시작, 로깅 스크립트 등.
* **진화적 의미**: 학습(harness) 환경과 실제(Production) 환경을 안전하게 격리하고 연결하는 훅(Hook)으로, 스킬의 내구성을 평가하는 요인입니다.

### 3.3. 작동 보이스 및 제약 (Voice & Ethical Bounds)
* **목적**: 에이전트가 어떤 어조와 태도로 반응해야 하는지를 통제합니다.
* **구성요소**: "겸손할 것", "코드를 직접 제시할 것", "단답형으로 말할 것" 등 시스템 프롬프트성 명령.
* **진화적 의미**: `autoresearch`는 에이전트의 답변 품질 점수가 낮을 경우, 이 보이스(Tone and Manner) 부분의 지시어를 변이시켜 자연어 처리 및 명령 순응도를 향상시킵니다.

### 3.4. 워크플로우 및 실행 매뉴얼 (Workflow Recipes)
* **목적**: 에이전트가 태스크를 달성하기 위한 구체적인 단계별 매뉴얼과 명령어 조합법.
* **구성요소**: 도구 사용법, 코드 작성 순서, 예외 처리 시나리오(`Escalation`), 완료 조건(`DONE`, `BLOCKED`).
* **진화적 의미**: 가장 활발한 변이(Mutation)가 일어나는 핵심 영역입니다. `autoresearch`는 `harness`에서 실패한 시나리오를 발견하면, 워크플로우 매뉴얼에 새로운 예측 불가능한 상황(Edge case)에 대한 대처법을 덧붙이는 형태로 스킬을 진화시킵니다.

## 4. autoresearch를 위한 진화 가능 영역 (Mutatable Attributes)
`harness`의 피드백을 통해 `autoresearch`가 수정을 시도할 핵심 "유전자(Mutatable Fields)"는 다음과 같습니다.

| 진화 타겟 | 변이(Mutation) 전략 예시 | 기대 효과 |
| :--- | :--- | :--- |
| **명령어 파이프라인** | 여러 Bash 명령을 하나의 병렬/파이프라인으로 압축 | 토큰 사용량 감소, 실행 속도 증가 |
| **에스컬레이션 조건** | 특정 에러 루프 발생 시 즉시 `BLOCKED` 처리 룰 추가 | 무한 루프 방지 및 Harness 비용 절감 |
| **성공/실패 정규식** | 작업을 성공했다고 확인하는 상태 검증용 정규식 강화 | 오탐(False Positive) 방지, 평가 정확성 향상 |
| **보조 Helper Scripts** | E2E 테스트용 Python/Node Helper 스크립트 파라미터 조정 | 특정 도메인의 복잡한 환경에서의 생존력(점수) 확보 |

## 5. 결론
이 구조에서 `gstack` 스킬 프레임워크는 단순히 사람이 읽기 위한 문서가 아닙니다. **실행 환경(Harness)의 평가 점수와 자율 피드백 루프(Autoresearch)를 통해 그 구조와 매뉴얼이 스스로 최적화되는 "진화형 함수"**입니다. 이 문서를 바탕으로 Claude Code 측에서 Harness 기반 E2E 벤치마클를 구성할 수 있습니다.
