## 1. 시스템 개요

BUSTAGO는 광주대학교 버스 정류장의 **혼잡도를 실시간 측정·예측**하여 학생에게 탑승 추천 정보를 제공하는 시스템이다. 4개 계층(HW · Backend · ML · Frontend)으로 구성되며, 외부 광주 BIS API와 기상청 API를 결합하여 단순 측정을 넘어 미래 예측까지 제공한다.

## 2. 4계층 아키텍처

```
┌────────────────────────────────────────────────────────────┐
│ Layer 4  Frontend                                          │
│  • Student PWA  (HTML/JS, Service Worker)                  │
│  • Admin Dashboard (실시간 카운팅 패널 + 지도)              │
│  • Nginx 정적 호스팅                                       │
└─────────────────────────┬──────────────────────────────────┘
                          │  fetch /api/* (JSON)
┌─────────────────────────▼──────────────────────────────────┐
│ Layer 3  Backend (Flask)                                   │
│  Blueprints: stations, predict, crowd, stats, recommend    │
│  • /api/stations, /api/weather/current                     │
│  • /api/predict, /api/stats                                │
│  • /api/route-recommend                                    │
│  • /api/crowd-count (POST: Jetson 수집)                    │
│  • /api/arrive, /api/lines, /api/gj-stops (광주 BIS 프록시) │
│  • flask-limiter Rate-Limit, CORS                          │
└──────┬───────────────────────┬─────────────────────────────┘
       │                       │
       │ predict()             │ SQL (MySQL or SQLite 폴백)
┌──────▼─────────────┐  ┌──────▼──────────────────────────────┐
│ Layer 2  ML        │  │ Layer 1  DB                         │
│  RandomForest      │  │  stations / predictions /           │
│  7 feature         │  │  weather_cache / crowd_counts /     │
│  CV F1=0.9962      │  │  routes                             │
│  (rf_model.pkl)    │  │  schema.sql + 자동 초기화           │
└────────────────────┘  └─────────────────────────────────────┘
       ▲                       ▲
       │                       │ POST /api/crowd-count (10s)
       │ feature input         │
┌──────┴───────────────────────┴─────────────────────────────┐
│ Layer 0  Hardware (현장)                                   │
│  • Jetson Orin Nano + USB 카메라 1대                       │
│    └─ counter.py (YOLOv11-nano + DeepSORT + Line Crossing)  │
│  • Raspberry Pi 4 + 7" 터치 LCD (Kiosk 모드)               │
│    └─ Chromium → Student PWA 전체화면                      │
└────────────────────────────────────────────────────────────┘
```

## 3. 컴포넌트별 책임

| 컴포넌트 | 위치 | 책임 |
|----------|------|------|
| **counter.py** | Jetson | 카메라 1대로 입장/탑승 Line Crossing → 인원수 집계 → 10초마다 POST |
| **Flask backend** | 서버 (또는 Pi) | API 7종 제공, ML 추론 호출, 외부 API 프록시 |
| **RandomForest** | `ml/models/rf_model.pkl` | 7 feature 입력 → 4단계 혼잡도 확률 출력 |
| **schema.sql** | `backend/schema.sql` | 5개 테이블 자동 생성 + 광주대 정류장 5개 시드 |
| **Student PWA** | `frontend/student/` | 정류장 선택 → 현재 혼잡도 / 6시간 예측 / 노선 추천 / 실시간 도착 |
| **Admin 대시보드** | `frontend/admin/` | 지도 + 실시간 카운팅 패널 + Jetson 연결 상태 |
| **Watchdog** | `hardware/watchdog_*.sh` | crontab으로 counter.py / chromium kiosk 자동 복구 |

## 4. 핵심 데이터 흐름

### 4.1 실시간 측정 흐름
```
USB 카메라 → counter.py (YOLO+DeepSORT 25 FPS)
           → in/board 카운트 → 10초마다
           → HTTP POST /api/crowd-count
           → DB crowd_counts 적재
           → Admin 패널 10초 polling으로 표시
```

### 4.2 혼잡도 예측 흐름
```
Student PWA 정류장 선택
  → GET /api/predict?station_id=X&hour=N
  → /api/weather/current로 weather/temperature 조회 (캐시)
  → 7 feature 구성 (hour, weekday, weather, temp, prev_*, route_count)
  → rf_model.predict_proba() → level 0~3
  → JSON 응답 → 색상/메시지 렌더링
```

### 4.3 대체 노선 추천 흐름
```
Student PWA 출발/목적지 선택
  → GET /api/route-recommend?station_id=X&hour=N&dest=Y
  → STATIC_ROUTES 또는 DB routes 테이블 조회
  → 각 노선마다 predict_congestion() 호출
  → level 오름차순 정렬 + 1순위에 recommended=true
  → JSON 응답 → 카드 UI
```

### 4.4 광주 BIS 실시간 도착 흐름 (2026-05-13 추가)
```
Student PWA 광주대 정류장(GJ3230 등) 선택
  → GET /api/arrive/<busstop_id>
  → backend가 광주 BIS arriveInfo API 프록시 호출
  → ARRIVE_LIST 추출 → JSON 응답
  → 도착 카드 렌더링 + 30초 자동 갱신
```

## 5. 외부 의존성

| 서비스 | 용도 | 키 위치 | 폴백 |
|--------|------|---------|------|
| 기상청 단기실황 API | weather/temperature feature | `WEATHER_API_KEY` (env) | weather=0, temp=20.0 기본값 |
| 광주광역시 BIS (gj_bis) | 시내버스 실시간 도착·노선 | `GJ_BIS_API_KEY` (config.py 기본값) | 502 응답 + UI에서 섹션 숨김 |
| MySQL | 운영 DB | `MYSQL_*` (env) | SQLite 자동 폴백 (`backend/bustago.db`) |

## 6. 비기능 요구사항 충족 방식

| 요구사항 | 구현 |
|---------|------|
| 응답 1초 이내 | RandomForest 추론 < 50ms, 캐시 weather 1시간 TTL |
| 24시간 무인 동작 | Watchdog crontab 2~5분 주기 자동 복구 |
| 카메라 1대 정확도 확보 | DeepSORT max_cosine_distance=0.3 중복 카운팅 방지 |
| 오프라인 내성 | Student PWA Service Worker + Admin 패널 stale 상태 표시 |
| 보안 | flask-limiter rate-limit, CORS, station_id 정규식 검증 |
