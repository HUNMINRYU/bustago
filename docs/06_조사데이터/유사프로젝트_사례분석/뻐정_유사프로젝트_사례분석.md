### 프로젝트 1: 뻐정 (Bbeojung.kr)

**기본 정보**

| 항목 | 내용 |

| 프로젝트명 | 뻐정 (Bbeojung.kr) |

**핵심 기술 스택**

- 언어/프레임워크: Python, Django + Nginx (백엔드), Bootstrap + CSS/JS (프론트엔드)
- AI/ML: SSD 네트워크 (COCO pre-trained, TensorRT FP16 변환) + LightGBM (버스 수요 예측)
- 하드웨어: 기존 CCTV 활용 (RTSP 통신), NVIDIA GPU (TensorRT + CUDA Stream)
- 데이터베이스: (명시 없음. 확인 필요)

**혼잡도 예측 방식**

두 가지 방식을 결합하여 혼잡도를 산출한다.
1. CCTV 영상에서 SSD 객체 탐지 모델로 정류장 대기 인원을 실시간 카운팅한다.
2. LightGBM 모델로 특정 버스의 시간대별 탑승 수요를 예측한다.
최종적으로 두 결과를 종합. 원활·보통·혼잡 3단계로 구분하여 제공하는 형식이다.

ML 모델을 학습시키기 위해, 약 200만건의 데이터를 활용하였으며, 60%는 모델 학습에. 20%는 학습 중간에 성능을 확인하는 용도로, 나머지 20%는 최종 성능을 평가하는데 사용하였다.

모델 예측에 참고한 정보는 7가지이다.

1. 광주 주요 정류장 8곳까지의 거리
2. 해당 정류장이 위치한 동네의 인구수
3. 정류장·노선·요일·시간대별 이용 통계
4. 해당 시간대에 얼마나 붐비는지 수치화한 값
5. 평일 or 주말의 여부
6. 날씨 정보 (온도·습도·풍속·감수량)
7. 무슨 요일인지

처음엔 Random Forest 모델을 사용하였으나, 학습에 30분 이상 걸리게 되며. 오차가 3.11로 나왔다. 그러나 이후 LightGBM 모델로 교체한 결과, 학습 속도가 15배 이상 빨라지고 오차가 약 20% 까지 줄어들게 되었다(최종적으로 2.3404). 추가로, 모델의 세부 설정값을 찾는 과정에서 여러 조합을 무작위로 시도해보는 Random Search 방식을 사용하였다.

**카메라/하드웨어 구성**

기존 설치된 CCTV에서 RTSP 프로토콜로 영상을 수신하는 방식이다. 별도 엣지 디바이스를 현장에 배치하지 않고, 서버 측에서 영상을 수신하여 처리한다. SSD 모델을 TensorRT로 변환 후 Engine 모듈만 분리하여 사용하였고, CUDA Stream을 통한 비동기 메모리 복사로 병렬 연산을 구현하여 기존 SSD 대비 약 24배 연산 속도를 향상시켰다.

트래킹 기술(예: DeepSORT)은 적용되지 않았다. 객체가 장애물이나 다른 사람에 가려져 인식되지 않는 문제에 대해서는 여러 각도의 CCTV 설치 및 파인튜닝·블렌딩으로 해결할 것임을 앞으로의 계획으로 제시하였다.

**우리 프로젝트 반영 가능 사항**

- 데이터 분석 방법: 뻐정에선 데이터를 분석하며 "요일마다 타는 사람 수가 다르다", "사람이 모이는 정류장 20곳이 8개 지역으로 묶인다"와 같은 패턴을 발견하여 예측 모델의 학습 재료로 활용하였다. BUSTAGO 또한 서울시 데이터나 광주대 현장 데이터 분석 시 이러한 숨겨진 패턴을 찾아내어 모델에 반영한다면 예측 정확도를 높일 수 있다.

- AI 추론 속도 최적화: 뻐정은 TensorRT라는 NVIDIA 최적화 도구를 사용하여 AI 모델의 처리 속도를 기존 대비 24배 빠르게 만든 바 있다. BUSTAGO의 Jetson 보드에서 동일한 방식을 적용 중이므로, 뻐정의 사례가 우리 프로젝트 설계가 올바른 방향임을 뒷받침하는 근거가 된다.

- 예측 모델 개선 가능성: 뻐정은 처음 Random Forest 모델을 사용하였으나, 이후 LightGBM으로 교체함으로써 학습 속도가 15배 빨라지고 오차가 약 20% 줄었다. BUSTAGO 또한 현재 Random Forest를 사용 중인데, 향후 LightGBM과 성능을 비교하여 더 나은 결과를 얻을 수 있는지 검토해볼 가치가 있다.

- 날씨 데이터 활용: 뻐정은 기상청의 온도·습도·풍속·강수량 데이터를 예측에 활용하였다. BUSTAGO 또한 동일하게 기상 데이터를 수집하여 반영할 예정이다. 뻐정에서 날씨 데이터를 추가했을 때 예측 정확도가 향상된 것이 확인되었으므로, 우리 프로젝트의 접근이 효과적이라는 근거가 될 수 있다.

**차별점 (BUSTAGO vs 이 프로젝트)**

- **트래킹 기술:** 뻐정은 트래킹을 적용하지 않아 동일 인물의 중복 카운팅 문제가 존재한다. BUSTAGO는 DeepSORT 추적 기술을 적용하여 사람마다 고유 번호를 부여, 특정 선을 넘을 때 딱 한번만 세는 방식으로 중복 문제가 없다.
- **객체 탐지 모델:** 뻐정은 SSD를 사용하였고, 당시 YOLO 초기 버전의 정확도 한계를 이유로 채택하지 않았다. BUSTAGO는 이후 정확도가 크게 개선된 YOLOv8-nano를 채택하였다.
- **혼잡도 단계:** 뻐정은 3단계(원활·보통·혼잡), BUSTAGO는 4단계(여유·보통·혼잡·매우혼잡)로 더 세밀한 구분을 제공한다.
- **하드웨어 구성:** 뻐정은 기존 CCTV + RTSP에 의존하여 카메라 각도·위치를 제어할 수 없다. BUSTAGO는 정류장에 전용 카메라를 설치, AI 처리 전용 보드 Jetson과 화면 표시 전용 보드인 Raspberry Pi를 따로 두는것으로, 각각의 역할에 집중할 수 있도록 설계했다.
- **프론트엔드:** 뻐정은 PC 웹 사이트로만 제공된다. 반면 BUSTAGO는 학생용 모바일 PWA + 7인치 터치 화면과 운영자 PC 대시보드로, 총 세 가지 환경을 모두 지원한다.
- **데이터 전략:** 뻐정은 광주광역시 BIS 데이터만 활용하였다. BUSTAGO는 서울시 공공데이터로 모델을 학습·검증한 뒤, 해당 모델을 광주대 환경에 **직접 적용**한다. 광주광역시 BIS API에 혼잡도 필드가 없어 별도 재학습 없이 국토부 표준 4단계 분류 체계가 공통 적용됨을 확인하였기 때문이다.
