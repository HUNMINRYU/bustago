# 광주 BIS API vs 서울 버스 API 혼잡도 기준 비교

> **작성일:** 2026-05-01  
> **작성 배경:** 4/30 교수 피드백 — "추정이 아닌 사실 확인 후 보고" 요구 반영

---

## 1. 작성 배경

교수 피드백: "광주 BIS API에 혼잡도 데이터가 없다는 것이 추정인가, 사실 확인인가?"

본 문서는 광주 BIS API와 서울 버스 API의 혼잡도 데이터 제공 여부를 API 명세 기반으로 실증 비교하여, 서울 ML 모델을 광주 정류장에 적용하는 것이 타당함을 근거 있게 기술한다.

---

## 2. 서울 버스 API (서울 열린데이터광장)

**API명:** `getBusPosByRtidService` (노선별 실시간 버스 위치)

| 필드명 | 설명 | 비고 |
|--------|------|------|
| `congestCd` | 혼잡도 코드 | **실시간 제공** |
| `plainNo` | 차량 번호판 | - |
| `lastStnId` | 마지막 정류장 ID | - |
| `isFullFlag` | 만차 여부 | - |

**혼잡도 코드 기준:**

| 코드 | 레이블 |
|------|--------|
| 0 | 여유 |
| 1 | 보통 |
| 2 | 혼잡 |
| 3 | 매우혼잡 |

- 실시간 제공: **Yes** (버스 이동에 따라 실시간 갱신)
- 데이터 출처: 서울시 버스정보시스템(BIS) — 실제 탑승률 기반

---

## 3. 광주 BIS API (광주 대중교통 정보시스템)

**확인 결과 (API 명세 기준):**

광주 BIS API는 다음 데이터를 제공한다:
- 버스 실시간 위치 (위도/경도)
- 도착 예정 시간
- 노선 정보, 정류장 정보

**혼잡도 관련 필드:** **없음**

- 차내 혼잡도(`congestCd` 또는 동등 필드) 관련 명세 **미존재**
- 탑승 인원 수, 만차 여부 등 혼잡도 추정 가능한 데이터도 **미제공**
- 확인 방법: 광주 BIS 공식 API 명세 문서 참조

> **결론:** 광주 BIS API에 혼잡도 데이터 없음은 **추정이 아닌 API 명세 기반 사실**임.

---

## 4. 비교 요약

| 항목 | 서울 버스 API | 광주 BIS API |
|------|--------------|-------------|
| 혼잡도 필드 | `congestCd` (0~3) | **없음** |
| 실시간 혼잡도 | **제공** | **미제공** |
| 위치 정보 | 제공 | 제공 |
| 도착 예정 | 제공 | 제공 |
| 탑승 인원 | 제공 (간접) | 미제공 |

---

## 5. 우리 프로젝트 적용 방식

서울 데이터로 학습한 RandomForest 모델을 광주 정류장에 적용:

**모델 스펙:**
- 알고리즘: RandomForestClassifier (n_estimators=10, max_depth=10)
- 교차검증 정확도: CV 0.9962 (5-fold)
- 모델 크기: 0.2MB

**입력 feature 7개:**

| Feature | 설명 |
|---------|------|
| `hour` | 시간대 (0~23) |
| `weekday` | 요일 (0=월~6=일) |
| `weather` | 날씨 (0=맑음, 1=흐림, 2=비, 3=눈) |
| `temperature` | 기온 (섭씨) |
| `prev_boarding` | 직전 시간대 승차 인원 |
| `prev_alighting` | 직전 시간대 하차 인원 |
| `route_count` | 정류장 경유 노선 수 |

**출력:** 혼잡도 레벨 0~3 (여유/보통/혼잡/매우혼잡)

---

## 6. 타당성 근거

1. **혼잡도 분류 체계 동일성:** 여유/보통/혼잡/매우혼잡 4단계 분류는 국토교통부 대중교통 표준 지침에 따른 것으로, 서울과 광주 모두 동일 기준 적용 가능.

2. **입력 feature의 범용성:** hour, weekday, weather 등 feature는 지역과 무관한 보편적 변수이며, route_count는 광주 정류장 실제 노선 수로 대체 입력.

3. **Yolov8 + DeepSORT 실측 보완:** 광주 현장 카메라 카운팅(Jetson)을 통해 수집한 실제 대기 인원 데이터를 `crowd_counts` DB에 축적, 향후 광주 특화 모델 재학습 기반 마련.

---

## 7. 결론

광주 BIS API에 혼잡도 데이터가 없음은 API 명세 기반으로 확인된 사실이다.  
서울 ML 모델을 광주에 적용하는 것은 혼잡도 기준 체계의 동일성 및 feature 범용성에 근거하여 타당하다.
