---

## 슬라이드 1: 표지
- 프로젝트명: BUSTAGO — 버스 정류장 혼잡도 예측 시스템
- 팀명: 같이타요 (광주대학교 캡스톤디자인 RISE)
- 발표일: 2026-05-21
- 팀원 이름 (팀원 기입)

## 슬라이드 2: 문제 정의
- 현재 상황: 광주대 셔틀 만차 때 학생들이 정보 없이 기다림
- 핵심 질문: "지금 타야 하나, 다음 버스를 기다려야 하나?"
- 발표 포인트: 설문조사 결과 (N≥50) 인용 — 대기 정보 부재로 인한 불편 경험 비율 강조

## 슬라이드 3: 솔루션 개요
- 3줄 요약: AI 카운팅 + ML 예측 + PWA 표시
- 시스템 블록 다이어그램 (카메라→Jetson→서버→학생/운영자)
- 발표 포인트: 기존 수동 운영 대비 자동화 포인트 강조

## 슬라이드 4: 기술 스택
- 보드별 역할: Jetson Orin Nano(AI 카운팅) / Raspberry Pi(Kiosk) / 서버(Flask+ML)
- 왜 Jetson인가: Pi 4는 2~5 FPS → DeepSORT 중복 카운팅 불가 / Jetson 25~40 FPS → 정확
- 발표 포인트: 교수 피드백 반영 — Pi→Jetson 변경 근거 명확히 제시

## 슬라이드 5: AI 카운팅 설명
- YOLOv11-nano + DeepSORT Track ID
- Line Crossing: IN 라인 / BOARD 라인
- 중복 카운팅 방지: 같은 Track ID 1회만 카운트
- 시연: counter.py --debug 화면 캡처 또는 실시간
- 발표 포인트: Track ID 기반 중복 방지 로직을 그림으로 설명

## 슬라이드 6: ML 혼잡도 예측 모델
- LightGBM 7 feature (hour, weekday, weather 등)
- Accuracy 0.9400 / F1(macro) 0.9319 / CV 0.9340±0.0215 / 모델 크기 1.7MB
- RF fallback 비교: Accuracy 0.9000 / F1(macro) 0.8850
- 서울 데이터 학습 → 광주 적용 (혼잡도 분류체계 국토부 표준)
- 발표 포인트: 국토부 표준 분류체계 근거로 전이 타당성 설명

## 슬라이드 7: 서비스 화면 — 학생 PWA
- 정류장 선택 → 혼잡도 4단계 표시 → 노선 추천 카드
- 실제 화면 스크린샷 삽입
- 발표 포인트: 학생 관점 UX 흐름 강조

## 슬라이드 8: 서비스 화면 — 운영자 대시보드

- Chart.js 시간대별 차트 + Leaflet.js 지도
- 실제 화면 스크린샷 삽입
- 발표 포인트: 운영자 관점 모니터링 강조

## 슬라이드 9: 시스템 아키텍처

- 발표 포인트: 확장성과 안정성 강조

## 슬라이드 14: Q&A
- 예상 질문 및 답변 준비:
  1. "광주 데이터가 없는데 서울 모델을 쓰는 이유?"
     → 국토부 혼잡도 분류 표준 동일 적용, 추후 Ground Truth로 파인튜닝 예정

     → DeepSORT 실시간 처리 필수 / FPS 부족 시 중복 카운팅 발생 → 정확도 저하 불가 피
